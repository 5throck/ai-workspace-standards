## Decisions
- Second meeting deliberately inverted the first: round 1 found what was MISSING, round 2 found what was PRESENT but wrong or excessive. Rule authors were asked to argue against their own rules.
- R5 and R7 reverse first-meeting decisions. Not because those were wrong, but because safety measures set deliberately strict turned out to have side effects: the RAG data-confidence cap would have pinned nearly every project at Amber (the exact failure the design warns about), and blanket MNPI exclusion from MCP would have killed the system's highest-value use case. Both kept but made conditional.
- Sharpest structural finding (R3): `procedures/*.yaml` and `skills/*.md` both described workflows, with no stated authority. Split by axis — procedures own WHAT/WHEN (machine-executed, versioned, pinned), skills own HOW (technique, judgment). Skills reference a procedure key instead of restating steps; a lint enforces it.
- R1 adds Stage 2.5 Thin Vertical Slice. The design's central claim ("data changes → report regenerates") was otherwise unverified until late Stage 5. Slice proves that single claim with DB core + one proxy chain + NPV + markdown report; no UI, auth, MCP, or alerting.
- R2 resolves an internal contradiction rather than removing agents: deal-analysis specialists build methodology during Stage 1-4 and become on-demand advisors after go-live. Left undocumented, someone would delete them as idle.
- R4 introduces a skill-existence bar (distinct trigger + distinct owner + non-trivial artifact). 5 merges applied, 93 → 88 total.
