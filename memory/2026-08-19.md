## Session Summary
docs(design): co-newbiz — three-stage review (AI 1st/2nd + human final), review bottleneck halved

## Changes
- `docs/designs/2026-08-19-co-newbiz-design_ko.md` — modified (§5.7 elevated to 2nd review, §6.6 KPI +2, §8.9-1 (d) review stages, §10.1-1 baseline annotated, §10.1-2 new, §10.3 entry condition relaxed, §11 ADR 0064–0067, §14.8-2 new, §15 O-16 revised + O-18/O-19)
- `CHANGELOG.md`, `memory/2026-08-19.md` — entries

## Decisions
- Per user direction: 1st/2nd review by AI for speed, final review by human. Human review-days drop ~37 → ~15-18; AI sessions rise ~190 → ~230-250. Calendar improves to 2-3 months with a dedicated reviewer, 4-5 months with a part-time one.
- Savings are uneven by artifact type, so estimated separately: repetitive/formal output (88 skills, 33 agents, checklists, docs) saves 60-70%; code and schema saves 40-50% since automated checks already exist; judgment-bearing output (regulation book, ADRs, security model, financial methodology) saves only 20-30%.
- No new 2nd-review machinery: §5.7's Phase 1.5 cross-validation matrix already does exactly this job and was elevated to a formal review stage. Same-domain review counts only as 1st stage and cannot substitute for 2nd.
- Central risk identified and mitigated: **an AI reviewing AI output shares its blind spots**, so correlated errors pass. Four mitigations — author ≠ reviewer enforced across domains; deterministic checks (lint, schema, tests) run before any inference-based review; humans sample-audit a percentage of AI-passed items to measure reviewer reliability; and silence is never read as approval.
- Automation bias treated as the biggest failure mode of the three-stage scheme. The human review screen shows no "PASS" stamp — output is split into verified / **could not verify** / needs judgment. `review_stage.unverified_items_json` is NOT NULL so an AI reviewer must explicitly declare what it could not check; an empty array is a declaration, a missing field is not.
- Human approval authority is unchanged. AI pre-review shortens reading time, not accountability. Regulations, gate approvals, investment decisions, the security/privacy model, and ADRs still cannot pass on AI review alone.
- O-16 pressure materially reduced: reviewer requirement drops from "one dedicated person" to "2.5 days/week or more". Still a Stage 0 entry condition, but no longer a stop condition.
- Human rejections of AI-passed items feed back into 1st/2nd review rule improvement, and rejection rate becomes a governance KPI alongside AI reviewer agreement rate.

## Open Issues
- O-18 (new): AI reviewer reliability threshold and audit sampling rate are unset — need Stage 0 actuals before fixing numbers.
- O-19 (new): whether to run AI 1st/2nd review on a different model family from the author. Would further decorrelate errors at the cost of complexity and spend.
- O-16 (revised): reviewer allocation still gates Stage 0, but at a lower bar.
- O-3 (carried): real deal for the manual pilot.
