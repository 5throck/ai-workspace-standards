## Local-only governance-ticket processing migration (ADR-0082)

## Session Summary
User-directed change: all GitHub Actions ticket processing moves to the local ZCode runner. The `on.schedule` trigger was removed from `nightly-tickets.yml` (workflow kept for manual emergency dispatch), and the 05:30 KST ZCode automation was rewritten from check-then-fallback to the sole primary batch (cap 50 tickets / ~5 h, same four gates, PR-only dev-sync landing, in-progress guard retained, scoped staging added). Decision recorded in ADR-0082; ADR-0071 marked superseded; §9.8 rewritten; spec registered.

## Decisions
- Remove only the schedule trigger, keep `workflow_dispatch`: preserves a manual emergency batch and the api-probe diagnostics without any scheduled CI processing.

- Runner lands via `dev-sync.ts --scoped-staging` with explicit task staging: prevents a repeat of the git-add-A sweep class (75f98784) on the shared local checkout.
- ADR renumbered 0080 → 0082: upstream landed unrelated ADR-0080 (pm team management authority) and ADR-0081 (delivery pipeline hardening) while local main was 28 commits behind; re-applied all edits on the fresh base.
