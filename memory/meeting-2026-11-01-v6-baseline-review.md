## Round 1 — Positions (all verified against real code)

### architect (summary)

Position: topology/promotion policy sound; three newest elements misplace state or understate contract work. Verified findings: (G-1) putting per-hub operational lifecycle state in the root-repo registry recreates the cross-repo-write/merge-conflict class N2 rejected — split static registry (root) from dynamic state (hub-local); (G-2) co-workspace has NO attach-existing-repo capability today — only provisioning path is fresh-scaffold-per-tenant (src/scaffold.ts shells new-project.ts); tenant trust pins to the tenant's own project dir; authZ is owner-principal-match or admin; path (b) is a new service capability requiring a named ADR-0092 addendum (attach mode, per-repo trust grant, ownership policy, working-tree concurrency model); (G-3) kanban spec vocabulary (P0–P3, queued/accepted/in-progress/blocked) matches neither existing ticket enums (low|normal|high|urgent; backlog|waiting|running|review|done|failed) and ticket.ts is @l2-propagate:false — upstream-request MCP pattern is the obvious cross-repo substrate; (G-4) hub-promotion.ts lacks a unit of transaction (suite = atomicity unit, temp staging + verify + atomic swap); l3-to-variant-pipeline classification is oversized for Phase 1 (1,712 lines); (G-5) structural gaps: no hub-resolve discovery; in-flight delegation disposition across UNAVAILABLE→RECOVERY undefined; session resource limits (per-tenant quotas exist, no per-hub cap); fan-in metric substrate unassigned; kill-criteria instrumentation missing (duplicate-validator.ts could be the drift detector); roster is 3 hubs + 13 spokes (not "16 spokes"); the v6 baseline design doc does not exist (ADR-0074 blocks Phase 1 landings). Proposals: I-1 registry/state split with hub-local .pipeline-state files + root-side hub-status reader; I-2 ADR-0092 Addendum 17 (attach mode, trust grant, key-per-spoke principal, worktree-per-session or serialized lock); I-3 keep existing ticket enums + SEV as separate field + upstream MCP hub routing + reprioritize appending to history[]; I-4 suite-atomic hub-promotion + Phase 1 ships preflight/FAIL-only with transform to 1.5; I-5 Phase 0 roster pinning, fan-in definition, drift-detector designation, design-doc creation as the actual Phase 0 gate.

### security-expert (summary)

Position: the two newest elements rely on trust boundaries that do not exist in today's implementation. Verified: co-workspace identity is a static `key:label` file entry (auth.ts:50-67) — no rotation/revocation/expiry/per-spoke scoping; process isolation (the default) runs tenant agents as same-uid siblings that can read gateway secrets (/proc/1/environ) and the shared data dir (access.ts:161-182 states this outright); provider key is stamped plaintext into tenant config (Addendum 9 mitigates with a dedicated low-limit key); co-security findings/evidence contain live targeting data (deferred co-price criticals, pending MCP decisions) — a spoke session must not read them. Gaps: (1) CRITICAL spoke session = whole-repo read of the hub; (2) CRITICAL no session identity binding — attribution in state_history/kanban is only as true as a static key label; (3) HIGH self-declared AVAILABLE is spoofable and flips the UNAVAILABLE block into an attacker-controlled switch; (4) HIGH state_history integrity is self-referential (repair-history precedent shows history rewriting is an accepted operation; service tickets are gitignored); (5) MEDIUM-HIGH kanban queue-jump/starvation (no rate limits); (6) MEDIUM-HIGH bootstrap clone is unpinned supply chain (user approves a prompt, not a pinned commit; docker side has digest pinning precedent, git side has none); (7) MEDIUM DEGRADED capability matrix has no security floor. Proposals: docker-isolation-only launch blocker; scratch-dir + ticket-queue-subdir-only mounts with denylist (services/, co-security docs/{findings,evidence,reports,security}, .env*, .git/); per-session dedicated low-limit keys; default-deny egress; key schema extension (key:label,expires,spoke-id), actor gateway-derived never client-asserted; root-side probe with TTL-lease divergence detection (declared-vs-probed divergence auto-forces DEGRADED + SEV ticket; lifecycle-manager operator); hash chain + root-side head anchor (repair-history forbidden on lifecycle chains); P0 user-only, spoke raises capped one level per 24h, global concurrent-P0 cap, 3-strike auto-freeze; SHA pinning at approval + VALIDATED = gitleaks scan + hook-integrity diff + bun audit + audit.ts green (hooks inactive until VALIDATED); never-in-DEGRADED list (pentest execution, verify-authorization issuance, auth-surface threat modeling, bootstrap/validation).

### automation-engineer (summary)

Position: buildable on real primitives, but three of six new elements cross existing machinery rather than extend it; Phase 1 over-packed; no design docs exist yet. Verified: docs/workspace-schema.json is hand-paired with templates/common/docs/workspace-schema.json under a hash-parity check (validate-templates.ts ~L1242) with exactly ONE sanctioned delta — per-session state_history churn permanently fails parity and a docs/ edit triggers full audit on every session-start write; current ticket states/priorities differ from the plan's lanes (schema-version bump + migration would ripple into qa-gate, doctor, upstream-server, ticket-run — an alias layer suffices); POST /sessions accepts only {variant, name?, description?} — project dir is scaffolded internally and relocated; no route accepts an external directory; deleteTenantData is fail-safe for attached dirs but detach semantics must be designed; sweepOrphanedScaffolds deletes any gw-<12hex> dir under Projects/ without a registry row at gateway boot — bootstrap temp dirs must avoid that namespace; hub fan-in for SCRIPTS is not derivable from the fleet report (scripts are not graph nodes) though skills/agents fan-in IS derivable; E2E harness patterns exist (TICKET_WORKSPACE_ROOT / UPSTREAM_WORKSPACE_ROOT env seams, mkdtempSync fixtures, in-process co-workspace server tests with stub hermes binary; local bare repo as hub_remote = zero GitHub). Proposals: registry = static only (hub name, hub_remote, capabilities, minimum_version, classifications; L1 copy reconciled same-commit) + operational state in hub-local .pipeline-state/hub-<name>.state.json (atomic tmp+rename write pattern); reuse scripts/automation-lock.ts verbatim for bootstrap locks; temp dir Projects/.bootstrap-<name>-<pid>-<ts> + same-device rename check + bootstrap-state.json recovery marker + boot-time sweep; alias layer P0↔urgent / queued→waiting / in-progress→running / accepted→review / blocked→waiting+blocked_reason; upstream MCP minimal extension (priority in status + read-limited reprioritize tool, audit-logged, per-directory mkdir lock with owner token already exists); co-workspace attach_dir = one focused service PR (route + lifecycle guards + tests, Projects/co-* constrained, explicit 409/detach delete semantics); Phase 1 keeps registry/bootstrap/hub-promotion/3 PRs, slips pipeline classification + preflight + script fan-in graphs to 1.5; FILE_TIME_BUDGETS rows for new tests.

### docs-writer (summary)

Position: documentable within existing conventions, but one pre-existing SSOT defect becomes worse and one active hazard: ADR-0098 §2.5 cites an "AGENTS.md glossary roles" registry that does not exist (dangling pointer), while v6 coins ~14 terms with no registered owner or collision check. Gaps: vocabulary has no canonical home; hub-local state-file format has no assigned spec owner and state_ref would ship as a permanently dangling pointer without an explicit "unresolvable from root by design" note; never-in-DEGRADED floor risks landing only in prose (house pattern: normative text + verification in the ADR addendum, ADR-0092 Addenda 14/15 precedent); Phase 0 says "design doc" singular but content spans at least four separable concerns (precedent: one design per feature, one registry entry; spec-check handles a split at trivial cost); probe reports and fleet-report hub section are new recurring outputs with undefined surfaces (docs/reports/ is the established location; retention rule needed); no human-facing surface for Phase 3/3.5 runtime features (docs/guides/ is the operator-guide surface); state names coined without a collision check against ticket statuses and variant_lifecycle vocab (ADR-0083 naming rule). Proposals: glossary table (~15-20 rows: term | definition | declared-by | normative home) inside the consolidation design doc + fix §2.5 pointer in the same landing (no new glossary file, no AGENTS.md body additions — pointer-style only); machine-readable vs prose split (schema enum for states + capability keys; alias table as machine-readable JSON; state-machine narrative in design doc; normative security floor in ADR-0092 Addendum 17); state-file format contract normative in design doc + SCRIPTS.md row; ADR cross-reference discipline (Addendum 17 scope line, consolidation ADR reverse pointer, N2 ADR "Amends" header, extend ADR-0092 References); split into two design docs (hub-consolidation + coworkspace-attach-mode), each spec-registered; probe reports docs/reports/YYYY-MM-DD-hub-probe-<hub>.md with keep-latest-N retention; docs/guides/hub-operator-guide.md (English-first); state-name collision check at design review + split enum into bootstrap_states vs operational_states so the machine distinguishes who may write which.

### auditor — RED-TEAM (verbatim key claims)

Position: "v6 no longer runs a pilot; it pre-builds the end-state the pilot was supposed to justify." Every new element is specified at production grade — 7-state machine, TTL-lease probes, hash-chained audit, alias-layer kanban, a net-new co-workspace API, a bootstrap service with 5 guarantees — for a delegation channel with zero recorded usage (verified: no hub-delegation requests in memory/ or tickets/; no .pipeline-state files anywhere; hub-promotion.ts does not exist). The prior meeting's core discipline — gate expansion behind pilot evidence — was reintroduced as scope inflation: the session path is a larger privilege grant than the N2 channel it was supposed to be gated by.

Strongest objections: (1) kill criteria cannot detect the failure mode that matters — nobody uses it (none is an adoption metric; "≥1 new silent drift" is unfalsifiable if the divergence detector works; "≥2 re-promotions" measures the Phase 1.5 pipeline, not the channel; no kill→action mapping); (2) self-service sessions are the largest engineering item with the weakest justification — attach mode breaks the normative tenant-identity invariant (Addendum 6: one active team per (principal, variant)); egress enforcement was deliberately left host-side (Addendum 2) and v6 re-opens it as net-new gateway work; per-spoke keyed identity requires a machine-identity class that does not exist; even docker mode exposes the whole seed Hermes home read-only (Addendum 7); most damaging: scratch-dir-only mounts mean the session cannot write the hub repo — an expensive read-only context loader whose product the hub PM must apply anyway; (3) state machine gold-plates 3 git checkouts — user's need is "distinguish repo-exists from service-ready" (2–3 bits); no consumer ACTS on AVAILABLE/DEGRADED divergence; root head-anchor contradicts the settled "registry = static only" (who writes it, under what authority?); (4) hub-bootstrap is incoherent as specified — if hub_remote exists, it's a trivial clone; if not, the real operation is create-remote + scaffold (two cases collapsed into one name); (5) kanban defends against an adversary that doesn't exist (1–2 tickets/month; sibling PM agents under the same gateway; user is in the loop at checkpoints); the one P0-bypass path has no negative test; (6) Phase 1 is overpacked to the point of delaying the only evidence-generating step; fan-in measurement "measures zero by construction" if it counts delegation traffic; rollback is missing a third axis (the attach API is a deployed service PR — reverting means image rollback + addendum supersession).

What would change my mind: (Demand) ≥3 recorded spoke→hub requests last quarter or user naming imminent interactive workload; (Scope) latency-coupled requirement stated, or named read-only mounts with explicit apply step, or a test overturning the seed-home exposure finding; (State machine) a named consumer acting on state + named divergence action wired to kill criteria; (Bootstrap) hub_remote clarified as an always-existing skeleton remote; (Kanban) evidence of multi-spoke contention; (Phase 1) parallelization plan or pilot scoped to 1 hub + 2 spokes.

Minimal path: pilot = ticket-only, 1 hub + 2 spokes (target: convention/field, no enum change); state = 3 values (MISSING/CLONED/READY) hub-local, DEGRADED/RECOVERY introduced on first real degradation; attach-mode: write Addendum 17, implement nothing until demand trigger (≥3 pilot tickets with hub-PM turnaround bottleneck, or explicit user request); cut Phase 1 to pilot-critical (1 hub promotion + registry schema v1 + contract update); bootstrap only when a second hub is actually needed, split into its two real cases; fix verification (golden-path E2E, P0-bypass negative test, third rollback axis, adoption metric: <N tickets/month after 90 days = the channel is the finding).

## Synthesis → v7 changes (user-approved baseline)

Accepted technical corrections (all five positions converged):
1. Registry/state split — root registry static-only + state_ref pointer; dynamic state hub-local `.pipeline-state/hub-<name>.state.json` (L1 parity gate + cross-repo write problem resolved)
2. State integrity — hub-local hash chain + ROOT-SIDE PROBE records head hash in its own reports (root reads, never receives writes — resolves the red-team's "who writes the root anchor" objection); divergence auto-forces DEGRADE + SEV ticket; TTL lease re-attestation
3. Kanban alias layer over existing enums + SEV separate field (no schema migration); upstream MCP extension (status+priority, read-limited reprioritize, audit-logged); P0 user-only; 24h/1-level spoke caps; 3-strike
4. co-workspace attach-mode named as net-new service PR via ADR-0092 Addendum 17: docker-isolation-only, scratch+ticket-queue-only mounts with denylist, per-spoke keyed identity (gateway-derived actor), dedicated low-limit keys, default-deny egress, per-hub session caps; never-in-DEGRADED security floor defined once in Addendum 17
5. Bootstrap precision: .bootstrap-* temp namespace (avoids gw- sweep), automation-lock.ts reuse, same-volume rename check, recovery marker, ENOTEMPTY concurrent guard; case split (remote-exists → clone = the body; remote-missing → user decision + ensure-github-repo/scaffold); SHA pinning at approval; VALIDATED = 4 security checks, hooks inactive before it
6. Two-enum state schema (bootstrap_states / operational_states) matching the user's 3+4 correction; state-name collision check per ADR-0083
7. Two design docs (hub-consolidation + coworkspace-attach-mode), each spec-registered; glossary table in consolidation design; §2.5 dangling pointer fixed same-landing; alias table machine-readable JSON
8. Phase 1/1.5 split: pipeline classification + consumes preflight + script fan-in graphs → 1.5 (protects promotion PRs from 1,712-line pipeline churn); skills/agents fan-in via fanIn2 fleet-report row in Phase 0
9. Kill criteria gain an adoption metric (<N tickets/month after 90 days = channel demand is the finding) + kill→action mapping (session path vs kanban vs full sunset) + third rollback axis (service PR revert)
10. In-flight delegation disposition across UNAVAILABLE: block new tickets/spawns, cancel in-flight sessions, RECOVERY→AVAILABLE requires probe re-verification
11. Roster pinned: 3 hubs + 13 spokes; co-architect = template creation; co-newbiz excluded

Partially accepted red-team input (user decision respected): 3a (ticket+kanban) precedes 3b (self-service sessions); adoption metric added; design work for attach-mode completed in Phase 0 (Addendum 17) while implementation is sequenced to 3b behind Checkpoint B. The full 7-state model and self-service structure remain per explicit user decisions (2026-10-31/11-01), with the red-team's demand-evidence concern recorded: the pilot's adoption data at Checkpoint B is the evidence gate before 3b implementation proceeds.

Preserved dissent (verbatim, not averaged): the red-team's Position, Objections 1–6, What-would-change-my-mind list, and Minimal Path as transcribed above. The red-team's Minimal Path was NOT adopted wholesale; items (c) attach-mode-defer-until-demand and the pilot scoping were partially reflected via 3a→3b sequencing and the adoption metric.
