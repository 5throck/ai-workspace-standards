## Decisions
- Investigated a proposed "Phase 1.5" experiment (apply Amendment 3's declarative `relates_to` schema to real workflows in `Projects/co-newbiz`) and found the premise didn't fit: co-newbiz already has its own independently-designed, complete, inference-based graph system (`scripts/co-newbiz/graph.ts` v0.4.0) that derives 7 node types / 12 edge types from existing structured SSOTs (procedure schemas, kill-criteria predicates, decision docs) with zero new frontmatter.
- User's chosen direction: recognize co-newbiz's approach as a second, equally valid "Inferential" graph-construction strategy within the ADR-0060 family (alongside Amendment 3's "Declarative" strategy) — documentation only, no code changes to co-newbiz or to the parent's `generate-skill-graph.ts`.
- Recorded the normative rule "an inferential graph MUST NOT introduce a second hand-maintained declaration of facts already authoritative elsewhere" as the amendment's load-bearing line.
- Recorded co-newbiz as "recognized precedent, not promoted standard" — explicitly not graduated to L0, with a three-stage revisit criterion (one project → no action; second independent project → compare extraction contracts; common contract confirmed → consider an opt-in generic extraction mode) so a second project's mere existence doesn't trigger premature generalization.
