## Decisions
- No new dependency added — `js-yaml` was already present in both root and `templates/common` `package.json`.
- `parseFrontmatter()` falls back to the pre-existing hand-rolled line parser when `js-yaml` rejects a frontmatter block (a few `docs/decisions/DEC-*.md` files have prose values with unescaped colons that are not strict YAML) — preserves zero-regression behavior for consumers outside this pass's SKILL.md-typed-relates_to scope.
- Kept the existing `source: string` edge field (semantic tag, used in the verifier's edge-identity key) unchanged rather than repurposing it for the plan's `{file, field, index?}` shape; added it as a separate `provenance` field instead, to avoid breaking the drift-diff engine.
- Edge `provenance` added only to SKILL.md-frontmatter-sourced edges (prerequisites, relates_to, required_skills) — not to variant.json/prose/document-layer edges, since those aren't the typed-relation review's motivating case.
- Post-implementation review caught two issues, both fixed: (1) `technical-feasibility` and `financial-modeling` had each independently declared `composes_with` on the other — two redundant symmetric edges for one relationship, violating the "declare once, either side" convention; removed the duplicate from `technical-feasibility`. (2) CHANGELOG/memory edge counts said 660 but the actual generated graph had 665 (now 664 after the composes_with fix) — corrected to match the real artifact.

## Open Issues
- Parser swap surfaced 4 previously-silently-dropped edges from multi-line YAML list frontmatter the old regex parser couldn't parse (e.g. `i18n-specialist` agent's `required_skills:` list) — net-positive correctness fix, not a regression, but worth flagging to the ADR owner.
- The verifier does not currently detect a `composes_with` relation declared redundantly from both sides (each side produces a distinct, individually-valid edge) — worth a follow-up validation rule, out of scope for this pass.
- `/sync` intentionally not run per task scope — full pipeline dry run is a follow-up before merge.
