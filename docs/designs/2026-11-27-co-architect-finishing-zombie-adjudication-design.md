## Problem

The co-architect project copy reports TRUE_DIVERGENCE + PROJECT_AHEAD against the template:
the project copy is at version 1.1.0 while its delivery source (the common base —
`templates/co-architect/` carries no override for this skill) sits at 1.0.3. The upgrade
engine's designed PROJECT_AHEAD protection (upgrade-project.ts recordProjectAhead) refuses
any delivery that would downgrade a project copy, and the 2026-11-26 wave's adopt grant was
correctly refused for exactly that reason.

- Zombie history: the "Workspace override" 1.1.0 content predates promotion; it was promoted
  into the project at template creation (bbf2ad2, 2026-11-02) from the pre-normalization
  workspace copy. f002984 (2026-09-09, PR #292) added only the `last_reviewed` line.
- Diff zombie 1.1.0 vs common base 1.0.3: the doctrine body is IDENTICAL. The only deltas:
  1. stale pre-normalization frontmatter (`metadata:` nested block with `type: process`,
     `prerequisites: none`, `gemini-parity: sync`, `last_reviewed: "2026-09-09"` — older
     than the template's 2026-11-08 restructure), and
  2. an empty `## Related Skills` stub section (heading + HTML comment, no content).
- Fleet state: co-security, co-work, co-design, co-game (and the workspace root
  `.agents` copy) all carry 1.0.3 from the common base; no variant template overrides exist.

## Verdict

The zombie's unique content is NOT real content: stale frontmatter styling superseded by the
template's newer doctrine, plus an empty stub. Decision-rule outcome: version-only bump —
the template is bumped ABOVE the zombie version so the version gate un-sticks and the engine
delivers normally WITHOUT any grant; the project copy is superseded at the next delivery.
