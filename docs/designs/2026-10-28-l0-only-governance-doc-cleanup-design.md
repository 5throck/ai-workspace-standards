## 0. Conclusion

Of the three governance docs carried in `templates/common/docs/governance/agents/`, one is removed from L1 delivery entirely (`pm-gateway-workflow.md` — its content is workspace-root operational procedure that has no project subject), one is forked as an L1-authored hand-maintained doc (`execution-plan-templates.md` — its content is project-applicable and load-bearing for project PMs), and one was already resolved yesterday (`workflows.md`, DEC-20261028-01). The removal requires a new L1-rendition transform in `applyGovernanceTransforms()` so the propagated instruction surfaces (L1 AGENTS.md / CLAUDE.md / GEMINI.md / HERMES.md) are retargeted in the same root PR — otherwise propagation regenerates dangling links. Per-project copies of `pm-gateway-workflow.md` are then deleted by a scripted pass whose ordering rule is absolute: **root PR merged first, per-repo upgrade-then-delete second**. The co-design workflows.md tombstone is cleared at its next upgrade so the project receives the DEC-20261028-01-sanctioned L1-authored rewrite.

## 1. Problem statement

`templates/common/docs/governance/agents/` holds three files. Two of them are verbatim L0 mirrors regenerated by the `agents-governance-docs` propagation domain (`scripts/propagation-map.json`, ~lines 295-304; `l2_drift_eligible: false`):

- **pm-gateway-workflow.md** describes workspace-root operational procedure: `bun scripts/ticket.ts` invocations (the script exists nowhere outside L0), L0-only ADR pointers (docs/adr/0078/0079/0080 — absent from all 16 projects), and L0-only roster rows (lifecycle-manager, skill-graph-analyst, auditor — each annotated "L0-only agent"). It is delivered byte-identical (md5 `bbe32212…`) to all 16 `Projects/co-*` repositories, where none of its operational referents exist.
- **execution-plan-templates.md** is also a verbatim mirror, but its content (execution-plan format, Row 0 Design Gate, E1–E5 exemptions, tier semantics) is consumed by project PMs; L1 `CLAUDE.md:256` / `GEMINI.md` / `CODEX.md:142` link its `#5.1`/`#5.1.1` anchors, and `scripts/sync-model-registry.ts:78` manages its model-ID literals. Only one line differs from L0 (a link swap). Forking it as L1-authored decouples project plan format from root-only edits while keeping the delivered path stable.

The workflows.md leg was resolved by DEC-20261028-01; its L1 copy is now a variant-scoped rewrite and the propagation domain excludes it. That decision explicitly noted "pm-gateway-workflow.md and execution-plan-templates.md remain verbatim L0 mirrors" — this design closes that remainder.

## 2. Goals / Non-goals

**Goals**

1. G1 — No scaffolded project receives L0-only operational governance content verbatim.
2. G2 — Every instruction-surface pointer to a removed L1 doc is retargeted by the propagation pipeline itself (no hand-edited L1 instruction files that the next `--governance-l1` run would clobber).
3. G3 — The project-applicable half of the corpus (execution-plan format) stays delivered, at the same path, with zero anchor breakage in L1 CLAUDE.md/GEMINI.md/CODEX.md.
4. G4 — Per-project removal of the retired doc is tombstone-free, auditable, and ordered so no upgrade run can hit the `TOMBSTONED (ERROR)` guard.
5. G5 — co-design converges with the fleet on the L1-authored workflows.md.

**Non-goals**

- N1 — No change to any L0 governance doc. `docs/governance/agents/*.md` at the root stays as-is; it is accurate for the root roster.
- N2 — No repair of pre-existing project-side dangling references (docs/adr/0078, CONSTITUTION.md links, docs/templates/, skill-modification-checklist.md) — follow-up ticket (§11).
- N3 — No extension of `--prune-removed` to `docs/` (§11).
- N4 — No change to the delivered `llm-interaction-standard.md` (shared binding standard, ADR-0098) beyond the workspace-schema.json allowlist hygiene fix.

### 5.5 Per-project removal script (automation-engineer)

One scripted pass over the 16 independent git repos under `Projects/co-*`. Contract:

1. **Inputs**: repo root list; target relpath `docs/governance/agents/pm-gateway-workflow.md`; expected content hash (SHA-256 of the L1 file, recorded immediately before the L1 `git rm`; the md5 prefix `bbe32212…` from the sweep is the cross-check).
2. **Per repo, in order**: (a) if the file is absent, log SKIP (idempotent re-run); (b) hash the working-tree copy — **mismatch = STOP and report, never delete** (a diverged copy may hold local adaptation; that is the U-20261028-001 lesson applied in reverse); (c) scoped cleanliness: `git status --porcelain -- <target>` must be empty — unrelated dirty files in co-abap/co-newbiz are explicitly allowed and must never be staged; (d) **upgrade-first** (see §6): run the project's standard upgrade flow so the retargeted instruction files and the forked execution-plan-templates.md land; (e) then `git rm <target>`; (f) commit **only** that path — never `git add -A`/`git add .` — with the standardized message below; (g) verify the commit touches exactly one file.
3. **Commit message** (English, §7 language policy): `docs: remove L0-only pm-gateway-workflow.md (L1 delivery retired; spec 2026-10-28-l0-only-governance-doc-cleanup)`.
4. **No tombstones**: the script must not invoke `--tombstone` for this path. After the root PR the template tree no longer carries the file, so the v1.79.0 manifest-baseline carry-forward auto-prunes the stale baselines and the deletion is tombstone-free (E14). Recording a tombstone would misclassify a template-departed path as a project-owned deletion.
5. **Output**: a per-repo table (repo | hash-match | upgrade | deletion commit | push), plus a STOP list for any hash mismatches or dirty-target refusals.
6. **Push policy**: commit locally by default; pushing is an operator-controlled flag per repo remote convention (the 16 repos are independent).

## 6. Sequencing

**Phase 1 — root PR (single landing)**: propagation-map exclude entries + note; the §5.2 transforms + guard; regenerated L1 instruction renditions; L1 pm-gateway-workflow.md deleted; execution-plan-templates.md forked; scaffold-markers narrowing (same commit as the deletion, E11); workspace-schema allowlist fix; optional validate-ticket-doc-commands / upgrade-project cleanups; spec registered. **This PR must merge before any phase-2 action.**

**Phase 2 — per-project pass**: the §5.5 script, per repo: upgrade → delete → commit. Any time after the merge; batchable.

**Why the ordering is absolute (reversed-order failure mode)**: if a project deletes `pm-gateway-workflow.md` while L1 still delivers it, the file remains in the template tree, the project's manifest still holds a delivered baseline for it, and the next upgrade's TREE SYNC observes a missing delivered baseline — `tombstoneSkip()` logs `TOMBSTONED` (ERROR) and refuses delivery (E14). That is U-20261028-001's resurrection vector with the polarity flipped: instead of a deletion being resurrected, a blocked upgrade run forces an emergency `--tombstone` record for a path that the template side is about to retire anyway — wrong classification, extra ceremony, and a guard state that the carry-forward would then have to unwind. Root-first makes every phase-2 deletion tombstone-free by construction.

**Per-repo upgrade-then-delete ordering (dangling-window elimination)**: the retargeted instruction files reach a project only via its upgrade. If the deletion lands first, that project's AGENTS.md/CLAUDE.md/GEMINI.md/HERMES.md pointers reference a now-deleted file until its next upgrade. Running the upgrade before the deletion in the same repo visit collapses the dangling window to zero: pointers are retargeted first, then the target disappears.

## 7. Risks and mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| R1 — Dangling pointers between root merge and a given project's phase-2 visit (instruction files referencing a file that still exists in that repo) | Low, timeboxed | Primary: upgrade-then-delete per repo (§6) — zero window for visited repos. Fallback for repos that cannot upgrade during the pass (e.g. upgrade tooling refuses on unrelated dirty trees in co-abap/co-newbiz): delete with the accepted short dangle, and file the pending upgrade as the follow-up — the operative PM rules live in the delivered `agents/pm.md`, so a dangling doc pointer degrades documentation, not enforcement. | R2 — Transform regex rot silently regenerating stale pointers on the next `--governance-l1` run | Medium (silent class) | Post-transform guard (§5.2): any residual `pm-gateway-workflow` literal in the five outputs throws. The known failure precedent (B-7 comment) is exactly this class. |
