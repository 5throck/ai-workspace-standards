## Defect

Fresh scaffolds emit exactly 3 agent-lifecycle-audit Check 5 warnings
(`agents/automation-engineer.md`, `agents/design-system-lead.md`,
`agents/contract-gate-engineer.md` — "Agent not registered in AGENTS.md").
The delivery is deliberate (design 2026-11-12-common-agents-for-common-skills:
agents reach real projects via the common copy at new-project instantiation;
`scripts/helpers/scaffold-markers.ts` pins the intent), but the project
AGENTS.md comes from the variant template whose roster lists only variant
agents — zero references to the three common agents. The regeneration promise
cannot land the rows: `regenerate-agents-md --variant` reads the agent list
from the variant's own `variant.json agents[]` only, so `templates/common/agents/`
never enters the roster — a machinery gap, not neglect.

## Delivery rule (verified)

new-project delivers to every project's `agents/`:

1. `copyDir(templates/common)` — every `templates/common/agents/*.md`;
   `agents/_COMMON.md` is removed post-copy (`NEW_PROJECT_L1_ONLY_AGENTS`).
2. The variant overlay (`templates/<variant>/`) copies over it — variant wins
   on name collision (e.g. `pm.md`, `i18n-specialist.md`).
3. `prune-country-scoped-assets.ts` (scaffold §2.4, after the overlay) removes
   country-scoped common agents AND their AGENTS.md roster rows for
   non-matching countries (`country_scoped_assets.agents` registry:
   `public-data-analyst` is KR-scoped). The roster scrub
   (`scrubAgentReferenceLines`) presupposes the template roster CAN carry the
   row — the template ships the superset, the scaffold prunes per country
   (same principle as the §6 skill-table superset note in regenerate-agents-md).

So the delivered common set = all `templates/common/agents/*.md` except
`_COMMON.md` and `pm.md`, i.e. today: automation-engineer,
contract-gate-engineer, design-system-lead, i18n-specialist,
public-data-analyst.

## Additional defect found during the fix (same class)

`validate-templates.ts` `findUndeclaredAgents` documents that nested
`agents/domains/` and `agents/_shared/` trees are out of variant.json scope
and are "indexed via the variant's AGENTS.md". co-safety is the only variant
with such a tree (37 nested agent files). The first draft of the fix derived
--variant rosters from `variant.json` alone and silently dropped those 37
index rows — caught in review of the regenerated diff (zero-lost-refs check:
`comm -23` of old vs new `agents/*.md` references). The final derivation is:

1. declared agents (`variant.json agents[]`, `pm` dropped, declared order
   preserved),
2. variant-tree undeclared agents (recursive scan, relpaths preserved, sorted) —
   the AGENTS.md index contract,
3. common-only agents (sorted; variant-shipped names dedupe to the variant
   entry because the overlay copy wins at delivery).

`--source` mode (L3 projects) now scans the project `agents/` tree with the
same recursive rule (the project tree already carries the delivered common
copies — behavior for flat trees unchanged).
