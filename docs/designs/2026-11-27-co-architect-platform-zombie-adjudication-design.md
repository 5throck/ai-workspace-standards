## Problem

Both co-architect project copies report TRUE_DIVERGENCE + PROJECT_AHEAD against the common
base: the project copies sit at 1.1.0 while the delivery source (the common base —
`templates/co-architect/` carries no override for either skill) sits at 1.0.3. The engine's
PROJECT_AHEAD protection refuses any delivery that would downgrade a project copy, so both
pairs have been stuck since the promotion (first seen 2026-11-13).

## Analysis (read-only evidence)

- Zombie history: both copies were promoted into the project at template creation
  (bbf2ad2, 2026-11-02) from the pre-normalization workspace copies; no project-side
  content commit since (prior history: 9d82711 2026-06-30, d8488e4 2026-06-29 — both
  pre-date the template's newer doctrine).
- Diff Pair A (zombie 1.1.0 vs common base 1.0.3): the doctrine body is IDENTICAL except
  the template carries a NEWER paragraph the zombie lacks (the `.agents/commands` lockstep
  note, spec `2026-09-25-propagation-engine-batch-design` §6-D8). The zombie's only
  extras: stale pre-normalization frontmatter (`gemini-parity: sync`, `prerequisites: none`,
  `last_reviewed: 2026-05-31`, trailing-space `metadata:` block — all older than the
  template's 2026-09-25 restructure) and an empty `## Related Skills` stub section.
- Diff Pair B (zombie 1.1.0 vs common base 1.0.3): same shape — doctrine body IDENTICAL,
  zombie extras are the same stale frontmatter set plus the same empty stub; the template's
  newer `last_reviewed` is 2026-11-08.
- Fleet state: platform-command-lifecycle-manager — every holding project at 1.0.3 except
  the co-architect zombie. platform-skill-lifecycle-manager — every holding project at
  1.0.3 except the co-architect zombie and co-abap-plugin at 1.0.2 (BEHIND base; the normal
  UPDATE flow / S1 SYNC_TEMPLATE_ADVANCE handles it at its next upgrade — noted, no action
  here). No variant template overrides exist for either skill.

## Verdict

Both zombies' unique content is NOT real content: stale pre-normalization frontmatter
styling superseded by the templates' newer doctrine, plus empty stubs. Decision-rule
outcome (both pairs): version-only bump — the common base templates are bumped ABOVE the
zombie version so the version gate un-sticks and the engine delivers normally WITHOUT any
grant; the project copies are superseded at the next delivery. The adopt-template grant
fallback (one PROJECT_AHEAD per sibling) was NOT needed and is NOT used.
