# Transform-Aware L0→L1 Parity Check for Platform Instruction Files — Design

- **Spec ID**: `2026-10-31-platform-parity-transform-check`
- **Date**: 2026-10-31
- **Author**: automation-engineer (PM Gateway dispatch; user-directed inspection finding 2026-10-31)
- **Status**: implemented (2026-10-31 — checker v0.5.0 landed, 7 unit tests green, audit gate green after `--governance-l1` reconciliation; Approved 2026-10-31, PM per user mandate)

## 0. Conclusion

`scripts/test-platform-parity.ts` gates `audit.ts` (Check: Platform parity, audit.ts:2996, Fail-capable) but checks the four platform instruction files (CLAUDE.md, GEMINI.md, CODEX.md, HERMES.md) at L0→L1 with **existence-only** semantics ("Just verify L1 file exists, don't compare content"). A stale, half-edited, or reverted L1 copy passes the gate. Decision: the checker **recomputes the publisher's own transform** — `applyGovernanceTransforms(readFileSync(L0), filename, l1Path)` from `scripts/propagate-to-templates.ts` (the `--governance-l1` writer, dev-sync step 4.51, ADR-0077 D11) — and requires the actual L1 content to match it byte-for-byte, modulo one volatile-marker tolerance (the `Last Updated: <date>` stamp). CODEX/HERMES section parity (deferred by spec `2026-09-25-verifier-platform-expansion-design` D3.5) is thereby closed not with a hand-written section-rule set but with the single canonical transform the publisher itself uses; the ADR-0093 informational-only gap for HERMES.md closes the same way.

## 1. Problem statement (verified 2026-10-31)

- test-platform-parity.ts:650-677 — the L0→L1 branch for the four platform files checks `existsSync(l1Path)` and reports `pass` unconditionally otherwise.
- PARITY_RULES entries for CLAUDE.md/GEMINI.md are dead config at this path: the informational branch never routes those files through `checkParity`/`compareFiles`. No other file consumes `PARITY_RULES` (repo-wide grep: only test-platform-parity.ts, and post-change only the `agents/pm.md` key is read).
- A live demonstration exists in the worktree on finding day: L0 CLAUDE.md/GEMINI.md were re-edited (graft→trail migration, in-flight sibling session) while `templates/common/CLAUDE.md` still carried the pre-edit content — the current checker reports PASS over a real divergence. At HEAD, L0 GEMINI.md `Last Updated: 2026-10-31` vs L1 `2026-10-31` (pre-commit hook re-dates committed files one-sidedly) — again PASS over drift.

## 2. Decision

1. **Recompute, don't re-describe.** The verifier imports the publisher's `applyGovernanceTransforms` and asserts `transform(L0) === L1` (after volatile-marker normalization). There is exactly one definition of "correct L1", and it is the function that produces L1. Hand-written section rules would be a second, drifting copy of that knowledge (the PARITY_RULES dead-config problem, repeated).
2. **Volatile-marker tolerance (inspection result).** The transforms emit no stamps (`publishGovernanceL1` writes `transformed` verbatim; no date injection anywhere in the transform chain). Volatility comes from the *content*: each platform doc carries a human-maintained `*Last Updated: <date> — …*` line that flows L0→L1 verbatim, and `.githooks` `pre-commit.ts:92-101` rewrites `Last Updated: <date>` tokens to the commit day in every committed file — so one-sided commits desynchronize the date between L0 and L1 while the annotation text stays equal. Tolerance: normalize `Last Updated: \d{4}-\d{2}-\d{2}` → `Last Updated: <date>` on **both** sides before compare. The annotation text after the date remains verified. Verified at HEAD: with this normalization all four pairs are transform-equal (CLAUDE/GEMINI raw-DIFF, date-normalized EQ; CODEX/HERMES raw EQ).
3. **Failure output is concise, not a full diff**: first divergent line number (post-normalization, 1-based), truncated excerpt of both sides, and both byte lengths, plus the remedy line (`bun scripts/propagate-to-templates.ts --governance-l1`).
4. **Dead-config removal.** PARITY_RULES keys `CLAUDE.md` and `GEMINI.md` are deleted. The `agents/pm.md` key and the whole L0→L1/L0→L2 extends/section logic are untouched.
5. **Missing-file semantics unchanged**: a missing L1 copy is still a FAIL (test (c)).

## 4. Risks and mitigations

- **Import direction**: test-platform-parity.ts → propagate-to-templates.ts. No cycle: propagate imports only `./helpers/layer-filter`, `./lib/*`, `js-yaml` — never audit or the parity checker; audit.ts invokes the checker as a subprocess, so no module-level cycle exists either. The publisher's run path is behind `import.meta.main` (propagate-to-templates.ts:2100), and the import is already proven safe by `tests/unit/governance-boundary-l1.test.ts:23`. Module-level side effects on import are limited to flag parsing (`args.includes(...)` reads the importer's argv; harmless — no top-level execution).
- **`die()` inside the transform** (`lib/error-handling.ts:341` → `process.exit(1)`): if the L0 structure drifts so a post-transform guard fires (workspace-boundary residue, surviving `pm-gateway-workflow.md` file link), the checker subprocess exits 1 with the guard message on stderr — the audit gate reports FAIL and the remedy (`--verbose` run / manual run) surfaces the guard text. Accepted: a guard fire is real divergence and must be loud; the checker does not suppress or swallow it.
- **Gate strictness**: the upgraded checker turns previously-invisible drift into audit FAILs. This is the point of the change; the reconciliation path is the publisher itself (already wired as dev-sync step 4.51, so every sync heals before commit).
- **False FAILs from stamp drift**: bounded by the date-only normalization (decision 2). The annotation text stays enforced.

## 5. Test plan

1. Unit (hermetic, temp-dir fixtures, no repo files mutated):
   - (a) tamper: L1 fixture = transform(L0) with one content token mutated → checker FAILs, discrepancy names the file;
   - (b) transformed-equal: L1 fixture = transform(L0) — content that differs from raw L0 in variant-scrubbed regions only (boundary-policy replacement, PM-Gateway pointer retargets) → PASS;
   - (c) missing target file → FAIL;
   - (d) stamp-drift tolerance: L1 fixture differing only in the `Last Updated` date → PASS;
   - (e) summary shape: mismatch reports first divergent line + lengths, not the full diff.
2. `bun run test:unit` green; `bun scripts/typecheck.ts` at baseline (0 new errors).
3. Acceptance: `bun scripts/audit.ts` green — the gate now runs the upgraded checker, so green proves all four L1 copies match their publisher transforms (after running `--governance-l1` to reconcile the in-flight drift the checker exposed).
4. Sync pipeline lands the change (dev-sync gates incl. version-bump test gate).
