## 2. Problem

1. Agent identity is invisible to fleet change tracking: 174 agent nodes and 636 agent-touching edges exist in the root graph, and every project graph carries its own agent roster, but the fleet report and history page diff **skill capabilities only** — a project adding a new agent or rewiring `agent → skill` relationships produces no signal anywhere.
2. The learning-extraction pass (resync Step 2e-6) consequently cannot see agent-side learning: new agent↔skill relationships appearing fleet-side, new agents referencing root skills, and relationship splits are all invisible to the nightly cross-reference.
3. The graph's structure has no human surface: layer composition (L0/common/variant), hubs, and "who uses this skill / what does this agent require" are answerable only by grepping a 973 KB JSON. The delivery story — what survives each hop (root → template → project) — is likewise raw-JSON-only, and the three hops use different layer vocabularies, which makes hand comparison error-prone.

## 3. Goals

- G1: agent-node and edge-type-level NEW/VANISHED change tracking in the fleet report, rendered per date on the history page, computed at render time from raw per-day projections (no precomputed diffs stored).
- G2: a dedicated **Agents** surface on the history page: agents per project, agent↔skill relationship counts by edge type, newest relationship changes, and the ≥3-project convergence rollup (learning candidates) mirroring the existing capability rules.
- G3: resync Step 2e-6 consumes the new diffs and files `learning:`-prefixed ticket candidates under the existing report-only / human-judged / no-silence rules; deployment via the runner's live-numbering rule with zero runner or manifest change.
- G4: `docs/skill-graph-structure.html` — self-contained, deterministic, CSP-compliant companion page with layer composition, ego-graph explorer, and per-hop juxtaposition; refreshed by the same fleet-report runs (daily sweep + Friday consolidation) with zero runner change.

## 5. Design

### 5.0 The measured premise correction (read first)

The approved brief stated: *"Snapshots already store full per-project `{nodes, edges}` arrays — so agent nodes and edge tuples can be diffed from existing snapshot data with ZERO snapshot-schema change."*

**That premise is measured false.** Per-project snapshot entries are `{nodes: N, edges: N, skills: N}` counts in every one of the six sampled dates spanning the series (2026-09-22 → 2026-11-23), and the writer (`skill-graph-fleet-report.ts:1566`) serializes counts by construction. There is also no git-history fallback: `Projects/` is gitignored wholesale (the fact v2.3.0's branch-evidence rule exists around), so past per-day graph contents are unrecoverable. Per-date agent/edge history therefore requires **some** new durable per-day record from rollout onward — a zero-new-state option does not exist.

The brief's preference order is honored as far as physics allows:

- **Compute-at-render is kept**: the snapshot stores raw projections (id/hash table + edge tuples), never precomputed diffs; NEW/VANISHED classification is computed at render by replaying consecutive snapshots — the same replay pattern the history page already uses for skills (history-report design §5.2 model note).
- **The zero-schema clause is replaced** by: additive optional per-project block, absent from all legacy snapshots, ignored by every consumer that does not know it. Rejected alternatives in §5.1.

### 5.1 D-A1 — additive per-project `agentGraph` snapshot block (Item A data layer)

From v2.6.0, each new snapshot's per-project entry gains one optional sibling to the existing scalars:

```
projects[<p>] = {
  nodes: 116, edges: 279, skills: 50,            // unchanged (legacy consumers)
  agentGraph: {                                   // new, optional
    n: [["agent:root/architect", "df886355fd897a2f"], …],   // [id, content_hash]
    e: [[0, 41, "used_by"], [2, 17, "references"], …]        // [nIdx, nIdx, edgeType]
  }
}
```

- **Scope of `e`**: edges with at least one agent-node endpoint (either direction), all edge types — measured 1,352 tuples across the 18 live project graphs.
- **Format**: deduped index form — node ids and hashes appear once in `n`; tuples reference indexes. Measured size: 54,987 bytes total across 18 projects (~52 KB on the 17-member fleet) vs 112,150 bytes full-form; +~35% on the current 149 KB snapshot. Snapshots accumulate ~+52 KB/day (~19 MB/year) — acceptable for a local, git-tracked artifact; growth is re-examined if the fleet adds dense-graph members (co-newbiz alone is 23.3 KB full-form).
- **Legacy tolerance is a hard rule**: `agentGraph` absent ⇒ legacy semantics everywhere (the history page renders an explicit "agent tracking begins <date>" note for pre-rollout dates — the honest-gap pattern the page already uses for missing snapshots; the audit freshness gate, ticket scans, and convergence logic read only pre-existing fields). A same-day rerun overwrites today's file including the block (same-day overwrite contract unchanged).
- Node `id` strings inside the block are hostile-string surface like any snapshot content: `\u003c`-escaping at the page's data block and `escapeHtml` at render (§5.2) cover them; snapshot JSON itself needs no escaping change.

**Rejected alternatives**:

| Option | Why rejected |
|---|---|
| The brief's literal zero-schema path (diff from stored arrays) | Premise false — arrays were never stored (§5.0); nothing to diff against |
| Side-car per-day artifact (`memory/skill-graph-metrics/agent-*.json` / JSONL) | Second artifact family to keep in sync; the audit freshness gate watches snapshots only, so a missing side-car becomes a new silent-gap class; the history page would read two file families with divergence risk |
| Reconstruct history from git | `Projects/` is gitignored wholesale — no history exists; unrecoverable by construction |
| Carry data forward inside the generated history page | Turns a generated artifact into a data store; determinism breaks (output would depend on its own previous output) |
| `graph-delta-log.ts` persistence | Wrong axis: it logs committed-vs-derived workspace drift (ADR-0084 §5), not a cross-date fleet time series |

### 5.2 D-A2 — per-date diffs and the Agents tab (Item A render layer)

**Diff computation**: the generator replays consecutive snapshots (existing NEW/VANISHED skills replay, extended to the new block). Per date row, two new summary classes join the model:

- `agentNodes: { added: string[], removed: string[] }` — agent ids NEW/VANISHED vs the prior snapshot (per project, aggregated fleet-side).
- `agentEdges: { added: { type: string, count: number, sample: [agent, other, project][] }, removed: { … } }` — **edge-type-level** summaries: per edge type, the count of NEW/VANISHED tuples plus up to 20 representative tuples ("+N more" beyond the cap). Full data for any date is one relative link away: the snapshot file itself (`../memory/skill-graph-metrics/snapshot-<date>.json`) — relative `<a href>` navigation is CSP-safe (`default-src 'none'` governs resource loads, not navigation), and keeps the page free of external references.

**Agents surface — decision: a dedicated sixth tab**, not an Overview section. Rationale: Overview is a fixed headline (coverage + class counts + trend strip) whose byte and attention budget must stay flat; agent relationship detail is a peer of Divergence / Delivery gaps in size and audience (triage sessions), and Timeline already owns the per-date diff feed. Tab contents:

1. Agents per project (count table, dynamic from the latest snapshot).
2. Agent↔skill relationship counts by edge type (fleet aggregate + per project).
3. Newest relationship changes (reverse-chronological feed of the per-date `agentEdges` classes).
4. **Learning-candidates callout** (D-A3) with the ≥3-project rollups.

**Reused constraints (history-report design, binding here)**: CSP meta `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'`; JSON data block `JSON.stringify(model).replace(/</g, "\\u003c")`; every dynamic string through `escapeHtml` (agent ids, project names, edge types, dates — including attribute contexts); deterministic output (no wall-clock markers); WARN-only emission failure (one stderr WARN; snapshot and exit code unaffected; no partial HTML).

**Byte budget**: 34 dates × ~0.5–1 KB of agent summaries ≈ +30 KB → projected ~205 KB on the current corpus, under the 300 KB budget (AC4). Growth ≈ +3 KB/day.

### 5.3 D-A3 — fleet-level agent/relationship rollup (learning candidates)

Mirrors the capability rules (`skill-graph-analytics/SKILL.md:90-106`) one level up, computed by the generator from the latest snapshot's projections + the root graph:

- **Agent capability convergence**: agents with the same bare `name` (scope-normalized — project graphs mint `agent:<project>/<name>`, the root mints `agent:root/<name>` / `agent:common/<name>` / `agent:<variant>/<name>`) converging on a single `content_hash` in **≥ 3 project graphs** and absent from the root graph → promotion candidate. ≥ 2 hashes → reconciliation candidate, never auto-promote.
- **Relationship convergence**: normalized edge tuple `(agentName, endpointKind+bareName, edgeType)` present in **≥ 3 project graphs** with no root-graph counterpart (root counterpart = same normalized tuple) → relationship learning candidate.
- Edge-type **splits** (same normalized pair carried under different edge types across projects) are listed as divergence-style candidates in the same callout.

The rollup renders in the Agents-tab callout as a report-only list. Filing belongs to the resync skill and human triage (Item B) — the fleet report never creates tickets.

### 5.4 D-B — resync Step 2e sub-step 6 extension (project-resync 1.10.0 → 1.11.0)

**Skill edit** (extends the bullet at `skills/project-resync/SKILL.md:235-241`; step numbering untouched — 2d/2e keep their numbers, so the runner's live-numbering lookup is unaffected):

After the existing skill-set/node-count sentence, sub-step 6 additionally consumes the agent/edge diffs from the current fleet-report snapshot and adds three candidate classes:

1. **New fleet-side agent↔skill relationships** (normalized tuples NEW in the window, converging in ≥ 3 projects, absent from root) → ticket candidate.
2. **Agents newly referencing root skills** (agent nodes NEW in the window whose edges point at skill names present in the root graph) → learning candidate for agent-capability promotion review.
3. **Divergent relationship splits** (same agent–skill pair under different edge types across projects) → reconciliation-style candidate.

**Ticket convention (explicit decision)**: the new classes file `learning:`-prefixed `kind: manual` tickets per the approved scope, and the title body **must contain the literal token `skill-graph`** — e.g. `learning: skill-graph agent↔skill used_by <agent>→<skill> converged in 4 projects, absent from root`. Rationale: the compound title keeps every existing routing rule functional simultaneously — Step 2e's `learning:` extraction routing (sub-step 2 convention), the fleet-report ticket scan's "title contains skill-graph" match, and analytics-triage greppability. The existing sub-step-6 candidates (skill sets / node counts) keep their current bare `skill-graph:` prefix unchanged. Report-only, human-judged promotion, and the no-silence rule are preserved verbatim — the extension only adds candidate classes to the same review pass (a landing still produces either requests or an explicit negative).

**Deployment path (state the mechanism)**: the nightly runner reads the resync skill's **live numbering at run time** (STEP G RULES, `runner-v5.snapshot.txt:39`) — extending the skill file's sub-step-6 body and bumping its version flows into the automation with **zero runner prompt or manifest change**. The prompt's "v1.8.0" parenthetical is a stale citation and harmless; this edit changes no step numbers.

**Mirror convention (measured, differs from the analytics skill's row)**: six root copies — `skills/` canonical + `.agents/`, `.claude/`, `.codex/`, `.gemini/`, `.hermes/` — all byte-identical today; **no template copies exist** for project-resync (nothing under `templates/*/skills/`). All six are edited together, byte-identical. The `.hermes` tree is a mirror despite not being a common-contract source.

**Registry propagation (same change-set convention as today's 1.5.0 analytics bump)**: `docs/VERSION_MANIFEST.md:74` → 1.11.0; `skills/SKILLS.md:50` row + change note; `docs/lifecycle/skills/project-resync.md` lifecycle record; `docs/templates/common-contract.json` `.common_platform_skills.project-resync.version` → 1.11.0 (version field only — the contract's source list stays as-is); regenerate `docs/skill-graph.json` + `docs/skill-graph.md` via `generate-skill-graph.ts` (the SKILL.md content change flows into graph nodes/hashes).

### 5.5 D-C — the graph-structure companion page (`docs/skill-graph-structure.html`)

**Separate page**, emitted by the same fleet-report run (auto-refreshed by the daily sweep and Friday consolidation — zero runner changes), inside the same HTML-emission block as the history page but an **independent try/WARN island**: one page failing never suppresses the other, and either failure is WARN-only per the v2.5.0 ruling. **No new CLI flags**: when HTML emission is enabled (`--html`/default), both pages emit; `--no-html` skips both. Rejected alternative: `--structure-html` / `--no-structure` flags — they would re-stale the `templates/common/scripts/SCRIPTS.md:340` usage row the machinery batch aligns today (its item C), for zero functional gain.

**Reused constraints (cited from the history-report design)**: self-contained single template-literal document, inline `<style>`/`<script>`, zero external references (no CDN/fonts/images, no `http(s)` URLs); CSP meta `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'` (script-src needed here too — the explorer is JS); data inlined as a `\u003c`-escaped JSON block; every dynamic string through `escapeHtml` (node ids are hostile-string surface); deterministic byte-identical output; UTF-8, English-only.

**Content**:

1. **Layer composition** (from the root graph's per-node `layer`): node-type × layer matrix (L0 216 / common 172 / variant:* 970 today), edge-type distribution, top hubs by degree (meeting-facilitation 273, k-dart 67, k-law 64, …; list capped at 20). Rendered as **inline SVG bars, no JS** — always visible even with scripts disabled.
2. **Ego-graph explorer**: searchable node picker (over the labels array) → renders the node's 1-hop neighborhood with **edge-type labels on every edge** — answering "who uses this skill / what does this agent require" directly. Client-side adjacency lookup over the inlined data.
   - **Byte budget, measured**: full compact payload = labels 40,681 B + type/layer enums 6,562 B + numeric adjacency 43,827 B (18-type enum) = **91,070 B (~89 KB)** → projected page ≈ **~130 KB** with shell, an **8.8× margin under the 800 KB budget**. The brief's fallback (inline root layer fully + per-layer summaries for common/variant) is recorded as the oversized-case alternative and is **not needed** on current data: the full graph fits with room for substantial fleet growth (budget revisit triggers only above ~700 KB).
3. **Layer juxtaposition** (compositional, per variant): for each of the 16 variants, three columns — root-layer slice (`layer == variant:<name>` nodes), `templates/<variant>/docs/skill-graph.json`, `Projects/<variant>/docs/skill-graph.json` — showing node/edge counts by type and top capability-level differences (normalized bare names present in project but not template, and vice versa; top 10 each, "+N more"). Each column states its own hop vocabulary (root `L0`/`common`/`variant:*`; template `variant:<name>` + `L0` residue; project uniform `L3`) — the structural story of delivery and drift, explicitly **not** a three-way topology render.
4. **History-page link card**: the history page gains a small card/tab entry linking to `skill-graph-structure.html` (relative href; ≤ ~2 KB growth; the history page keeps its own budget, AC12/AC4).

## 13. Addendum — root git-history backfill for the Agents timeline (owner-approved addition, 2026-11-23)

### 13.1 Premise refinement (refines §5.0)

§5.0's "no git-history fallback" holds **only for the root repo's view of `Projects/`** (gitignored). Two retroactive sources exist and are in scope for the **ROOT only**:

1. **Root `docs/skill-graph.json` full commit history** — the graph is regenerated at landing time (audit's graph-freshness gate keeps it fresh), so its git log is a near-complete **commit-granularity time series** of root structure, including agent nodes and agent↔skill edges (`used_by`, `references`). Measured: **340 commits** touching the file, 2026-08-24 → 2026-11-23, **76 distinct commit dates**.
2. **`docs/graph-deltas/**` where present** — partial, statistics-level (measured: 2 git-tracked files under `docs/graph-deltas/2026/`). Cited as corroboration, **not consumed** by the backfill (different axis, incomplete coverage).

Consequently, §5.1's rejected-alternative row "Reconstruct history from git" remains true **for per-project history** and is **superseded for the root graph** by this addendum. **Per-project retroactive reconstruction via each project's own repo history is explicitly out of scope** (cost/value — recorded as future work; the forward `agentGraph` block covers per-project history daily from rollout, §5.1).

### 13.2 Mechanism — durable backfilled series, emitted in-run, no new flags

**Decision: the backfilled series lives in a durable root-level file, `memory/skill-graph-metrics/root-backfill.json`, rebuilt by a deterministic bounded step inside fleet-report v2.6.0's HTML-emission path** (the owner-sanctioned "separate emit-time generator step" form). One-shot semantics: the step always rebuilds the **full** series from HEAD (no incremental state) — idempotent and re-runnable by construction.

- **Rebuild policy**: the step reads the file's recorded `headSha` and compares it to `git rev-parse HEAD` — equal and parseable → **skip** (typical run: ~0 added cost, file read only); HEAD advanced or file missing → one full replay (~2.3 s measured, §13.3). Skipped under `--no-html` (the file feeds pages only). No new CLI flags.
- **Extraction**: enumerate `git log --format=%H%x00%cd --date=short -- docs/skill-graph.json` (committer date = landing date); per commit, `git show <sha>:docs/skill-graph.json` **full-blob parse** (not `log -p` — diff parsing is rename/format-change-proof this way); extract agent nodes (`type === "agent"` → `[id, content_hash]`) and agent-touching edge tuples; collapse to one row per commit date. File shape: `{ provenance: "git-backfill", headSha, path, rows: [{ date, commitCount, schema, agents: [[id, hash]…], edges: [[aIdx, oIdx, type]…] }] }` — **deterministic**: no wall-clock markers; `headSha` is content, so a rerun at the same HEAD is byte-identical (**AC-A2**).
- **Why a durable file, not emit-time inlining from a subprocess every run**: keeps the daily `--json` runner's runtime independent of repo history after the first post-landing run; the file is git-tracked (durable across clones, like the snapshots), consumable by **both** the Agents tab and the structure page without re-plumbing, and the "no git plumbing in fleet-report" spirit from the machinery design's MP constraints is honored for steady-state runs — the only git work is `rev-parse` (cheap, staleness check) plus the bounded replay when HEAD moved.
- **Failure isolation**: the backfill is a **third WARN island** alongside the two pages — any failure (non-repo context, oversized corpus, parse error) is one stderr WARN naming the reason; snapshot, `--json` stdout, exit code, and the other islands are never affected (fail-open, v2.3.0 posture; SKILL_GRAPH_ROOT test fixtures simply have no backfill). On failure the previous `root-backfill.json` stays (stale-honest) or stays absent (Agents tab renders snapshot-sourced days only, with a note).
- **Snapshot contract untouched**: `root-backfill.json` does not match the `snapshot-YYYY-MM-DD.json` pattern, and the audit freshness gate counts exact filename matches only (machinery design SF-T8 semantics) — **AC-A4**. Runner prompt / `prompts.manifest.json`: zero bytes (**AC-A4**).

**Consumption**: the Agents tab renders the backfilled root rows in the timeline with commit-granularity dates and a visible **"backfilled from git history"** provenance marker distinguishing them from snapshot-sourced days (**AC-A1**); the structure page's layer-composition section gains a compact root agent/edge count-over-time line from the same file (a few KB). Page byte impact: 76 rows × ~250 B ≈ **~20 KB** → history-page projection ≈ **228 KB**, still under its 300 KB budget (AC4 re-measured, holds).

### 13.3 Boundaries (accuracy contract)

- **Commit-granularity only**: intra-commit-day states never existed — the graph is regenerated at commit time (`generate-skill-graph.ts` runs at landing), so the backfilled timeline's finest resolution is the commit. Uncommitted regenerations (e.g. today's 20:25 working-tree file vs. the last committed blob) do not exist in the timeline until landed. State this on the page next to the provenance marker.
- **Stale windows are faithfully replayed as stale** — periods where the graph was not regenerated appear as repeated identical states, not interpolated gaps; that is the structural limit of the source and is noted, not smoothed.
- **Runtime cap (measured)**: full replay of the current corpus = 340 commits / **2,348 ms** wall (~7 ms/commit incl. blob fetch + JSON parse). Safety cap: hard maximum of **1,000 commits** replayed per run (~7 s expected ceiling); exceeding it aborts the island with a WARN naming the cap (raise the constant deliberately, never silently). The cap's implied date floor is the file's birth (2026-08-24 measured) — no date constant needed.
- **Schema drift**: pre-v2 commits (schema v1 → `deg/v2` on 2026-10-08, ADR-0060) are extracted best-effort by `type === "agent"`; each row records the blob's top-level `version` in `schema`; NEW/VANISHED computation across the v1/v2 boundary uses bare-name normalization only (rows are self-contained; no cross-schema id diffing).
- **Out of scope**: per-project retroactive reconstruction (§13.1); consuming `graph-deltas/**`; any change to snapshot files, the runner prompt, or `prompts.manifest.json`.
