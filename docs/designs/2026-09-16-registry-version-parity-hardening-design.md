# Registry Version Parity Hardening — 2026-09-16

## 1. Overview

Lands Wave 1 of the 2026-09-15 template-fleet review remediations — three
validator-hardening tickets in one batch (T-20260915-013, T-20260915-001,
T-20260915-004). Each closes a "registry version went stale and no gate
noticed" gap found by the scoped review (`docs/reports/2026-09-15-project-review-template-fleet.md`,
findings H10, H8, M7).

## 2. Problem

1. **H10 — platform-skill contract versions unchecked (T-20260915-013)**.
   Check H in `scripts/verify-platform-lifecycle.ts` is exists-only: it proves
   each `common_platform_skills` entry was propagated to
   `templates/common/<platform>/skills/`, but never compares versions, so a
   bump on either side of the propagation edge is invisible. 9 skills are
   double-registered in `common_skills` AND `common_platform_skills` in
   `docs/templates/common-contract.json` with no equality check between the
   two sections. The reverse exists→listed coverage sweep in
   `checkCommonContractReverseCoverage` covers only the
   `templates/common/.claude/skills/` tree — the `.gemini` tree has no arm.
2. **H8 — cross-registry SCRIPTS.md version parity (T-20260915-001)**.
   `templates/common/scripts/SCRIPTS.md` is hand-maintained and intentionally
   excluded from L0/L1 content parity (`registryFiles`), so its Version cells
   went stale vs `scripts/SCRIPTS.md` for five feature scripts across three
   consecutive bump rounds — invisible to every gate until the manual PR #929
   reconciliation. No standing check existed.
3. **M7 — VERSION_MANIFEST has no reconciliation gate (T-20260915-004)**.
   `docs/VERSION_MANIFEST.md` is generated by
   `scripts/generate-version-manifest.ts` with no drift gate, and the
   collector counts `scripts/experiments/infer-graph-from-phases.ts` (a
   CLI-less file) — "Scripts: 93" vs the real 92.

## 3. Requirements and acceptance criteria

### 3.1 C-CM-03b — platform-skill version parity (T-013)

- **R1**: For every `common_platform_skills` entry, for every declared
  platform tree (`claude_source` → `.claude`, `gemini_source` → `.gemini`,
  `agents_source` → `.agents`), the contract `version` must equal the
  SKILL.md frontmatter `version:` of the propagated copy under
  `templates/common/<platform>/skills/`.
- **R2**: A missing propagated copy, a missing contract version, or a missing
  frontmatter version is an Error — never a silent skip (same direction as the
  1.28.0 M5 fix for C-CM-03/03a: unverifiable parity must fail loud).
- **R3**: A skill present in BOTH `common_skills` and
  `common_platform_skills` must carry the same version in both sections.
- **R4**: The reverse exists→listed coverage sweep must also cover the
  `templates/common/.gemini/skills/` tree, mirroring the existing `.claude`
  arm (severity stays WARN — promoting `common_platform_skills` to a hard
  inventory remains an open scope decision).
- **A1**: With current repo data, validate-templates reports 0 C-CM-03b
  errors (all 12 entries x 2 platforms verified equal; all 9
  double-registrations equal).
- **A2**: Mutating either side of any parity pair (contract version, propagated
  SKILL.md frontmatter, or one section of a double registration) produces a
  C-CM-03b FAIL.

### 3.2 l0-l1-scripts-registry-version — SCRIPTS.md version parity (T-001)

- **R5**: For every script name with a registry row in BOTH
  `scripts/SCRIPTS.md` and `templates/common/scripts/SCRIPTS.md`, the Version
  cells must be identical; mismatch is an Error.
- **R6**: Row presence differences (a name in only one registry) stay out of
  scope — verify-scripts.ts owns ghost/unregistered rows.
- **R7**: The row parser is a small exported pure helper
  (`parseScriptsMdRegistry`) that unit tests import; it matches only the
  section whose heading is exactly "Registry" (L0 also carries a "Registry
  Scope" prose section that a startsWith-based finder would wrongly match).
- **A3**: With the L1 data fixes applied (§5), the check reports 0 errors.
- **A4**: Changing one Version cell in either registry produces a FAIL naming
  the script and both versions.

### 3.3 VERSION_MANIFEST --check gate + experiments exclusion (T-004)

- **R8**: `scripts/experiments/**` is excluded from the CLI script collection
  (count AND table); the manifest note says so.
- **R9**: `generate-version-manifest.ts --check` regenerates the manifest in
  memory and compares against `docs/VERSION_MANIFEST.md`: exit 0 on match,
  exit 1 with a concise line diff on drift. The `**Generated**:` timestamp
  line is normalized on both sides so the comparison is deterministic.
- **R10**: Contexts without a committed manifest self-skip (exit 0), mirroring
  the ADR-0073 Amendment 1 self-skip pattern.
- **R11**: audit.ts auto-activates the gate in the established style of the
  skill-graph drift gate (ADR-0060) and the upgrade-coverage gate (ADR-0073):
  spawn when the collector exists, Fail on non-zero exit, Pass otherwise.
- **A5**: `bun scripts/generate-version-manifest.ts --check` exits 0 on the
  regenerated tree; appending any line to the manifest makes it exit 1.
- **A6**: The regenerated manifest reports **Scripts: 92**.

## 4. Check homes and rationale

- **C-CM-03b + the .gemini reverse arm live in `scripts/validate-templates.ts`**
  (inside `checkCommonContract` / `checkCommonContractReverseCoverage`, next to
  C-CM-03/03a and C-CM-04). validate-templates is the standard battery run by
  dev-sync and CI on every change; the contract-compliance checks already live
  there. Check H in verify-platform-lifecycle.ts stays exists-only: it remains
  the quick propagation linter for per-variant runs, and duplicating version
  logic in two homes would create two things to keep in sync.
- **l0-l1-scripts-registry-version lives in `checkL0L1ScriptParity()`**
  alongside the existing l0-l1-script-parity and l0-l1-subdir-parity checks —
  same function, same L0/L1 registry inputs, same severity vocabulary.
- **The --check gate lives in `scripts/audit.ts`** after the model registry
  gate, following the exact spawn/exit-code/output shape of the skill-graph
  (ADR-0060) and upgrade-coverage (ADR-0073) gates. The checker self-skips so
  contexts that carry the collector but no manifest (L2/L3 projects) stay
  green without per-project wiring.
