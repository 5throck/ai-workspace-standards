## 1. Problem statement

Four defects reported by the co-deck project after the 0.30.x template delivery. Each report was reproduced independently in the workspace before the fix (requester diffs were not applied).

| Ticket | Layer | Symptom (verified) |
|---|---|---|
| U-001 | L0→L1 script | `bun scripts/validate-templates.ts` in a project root without `templates/` exits 1. An import-time guard calls `process.exit(1)` before `main()` can run its own "not applicable" skip. Reproduced: HEAD copy exits 1 in a temp L3 tree; fixed copy exits 0. |
| U-002 | L0→L1 scrub | L1 `CODEX.md` keeps the body citation "(CONSTITUTION §11)" under an L0-ONLY marker that says the strip is complete. The prose scrub keys on the literal `CONSTITUTION.md`, so a bare `CONSTITUTION §N` citation passes through. |
| U-003 | L0→L1 script | `regenerate-agents-md.ts`: (1) a flat `tier: low` key is ignored, so the agent renders as the "medium" default; (2) a single-token `role: specialist` is printed as role text; (3) the target AGENTS.md is always rebuilt from the L1 template, which discards every variant-authored line outside the VARIANT-* blocks. |
| U-004 | L2 template | The co-deck template lacks the project's Font Parity rule (co-deck DEC-20261110-02, PR #216), so whole-file delivery drops it. The report also asks the template to carry stage-numbered `phases` frontmatter for four agents. |

## 2. Design

### U-001 — remove the import-time exit

Delete the module top-level `templates/`-missing guard in `scripts/validate-templates.ts` (v1.76.1). `main()` already returns 0 with `not applicable: no templates/common (variant/project context)` when the tree is absent. One absence handler, one exit path. Regression test: `tests/unit/validate-templates-l3-skip.test.ts` copies `scripts/` into a temp root without `templates/` and asserts exit 0 plus the summary text.

### U-002 — scrub rule A-10

Add prose rule A-10 to `scripts/lib/constitution-scrub.ts` (v1.3.0): `\bCONSTITUTION(?=\s*§)` → `context.md`. It is the same projection as A-4 (`CONSTITUTION.md §3.3` → `context.md §3.3`). Code files and JSON keep their existing behavior (the prose arm only). Root `CODEX.md` is unchanged: L0 may cite CONSTITUTION. The L1 copy is regenerated by the `/sync` governance-l1 publish step (`dev-sync.ts` step 4.51, `--apply --governance-l1 --docs`). Tests: three A-10 cases in `tests/unit/scrub-constitution-refs.test.ts`.

### U-003 — tier, role, in-place mode

`scripts/regenerate-agents-md.ts` v1.5.0:

- `resolveTier`: nested `tier.claude` wins; the flat `tier:` key is the fallback; "medium" only when neither exists.
- `resolveRole`: a role with no whitespace is a category token. Fall back to the description, without wrapping quotes and without the `Use when:` trailer.
- `selectBase`: when the target AGENTS.md already carries at least one VARIANT-* START/END pair, update the present blocks in place and keep all static content. Report absent blocks. Do not invent them. A target with no markers, or `--from-template`, keeps the original full rebuild. `l3-to-variant-pipeline.ts` (v1.23.1) passes `--from-template` from its PHASE 3.5 auto-fix, so the pipeline's behavior does not change.
- The CLI is guarded by `import.meta.main`, so the pure helpers are unit-testable. Tests: `tests/unit/regenerate-agents-md.test.ts`.

Verified on a copy of `Projects/co-deck`: in-place mode keeps the file at 666 lines (it was 650 before; the full rebuild produced 499). Low-tier agents render "Low". i18n-specialist renders its description.

### U-004 — carry the Font Parity doctrine; keep the phase contract

Accepted (templates-only):

- `templates/co-deck/docs/co-deck.context.md`: Content Rule 7 "Font Parity (PDF ↔ HTML)". This is the project's rule 9 text. The template list ends at rule 6, so the rule is renumbered to 7. Version footer 4.7.
- `templates/co-deck/skills/html-build/SKILL.md` v1.7.0 (the mandatory "Font Parity" section) and `skills/pdf-export/SKILL.md` v2.1.2 (the "Font source of truth" paragraph). Both are byte-ported from the project and copied to all five platform mirrors. `skills/SKILLS.md` rows are updated.

Rejected (recorded judgment, flagged for the user): stage-numbered `phases` frontmatter (`html-build [5,6,7,8]`, etc.). `templates/co-deck/docs/phase-definitions.md` is the declared authority. It states that agent frontmatter `phases:` uses delivery phases 0–6, that these numbers are "the skill/agent contract" and "never renumbered", and it maps html-build `[4]` to Stages 5–8. The project's own `phase-definitions.md` is byte-identical and still says the same thing. So co-deck review finding H-3 (2026-11-11) changed four frontmatter values without changing the authority file. To adopt stage numbers, run a co-deck design flow that changes `phase-definitions.md`, `variant.json` `skill_manifest`, the AGENTS.md phase-gate, and every agent together. Until then the template keeps `[4]`.
