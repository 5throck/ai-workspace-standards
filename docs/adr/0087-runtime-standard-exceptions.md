# ADR-0087: Runtime Standard Exceptions — Tool-Owned Node Shims and Documented Variant Exceptions

**Status**: Accepted
**Date**: 2026-09-23
**Deciders**: PM per user direction
**Related**: ADR-0036 (Script Migration — sh/ps1 → TypeScript/Bun Runtime), design doc `docs/designs/2026-09-23-runtime-standard-exceptions-design.md`

## Context

ADR-0036 standardizes workspace automation on single TypeScript files
executed by `bun`. A fleet-wide audit (2026-09-23) of residual Node.js
usage across the workspace root and templates found four classes of
`node`-adjacent code. None is an unrecorded violation, but ADR-0036 does
not mention them, so audits and new contributors cannot distinguish
compliant exceptions from drift.

1. **graft tool-owned shims.** `.claude/helpers/graft-hooks.cjs` and
   `graft-statusline.cjs` (workspace root + `templates/common`) carry
   `#!/usr/bin/env node` shebangs, and the graft hook blocks in 15
   `settings.json` files (root, common, 13 variants) invoke them with an
   explicit `node` command. The permission lists also carry defensive
   `Bash(node dist/cli.js:*)` / `Bash(npx graft:*)` lines. These files are
   generated and regenerated by the graft CLI (`graft init`); the
   2026-09-12 graft wiring refresh (CHANGELOG) established that aligning
   to graft's canonical output — not hand-editing it — prevents churn.
   The shims also assume a node/npm ecosystem internally (`npm root -g`
   fallback).
2. **co-deck Playwright browser tests.**
   `templates/co-deck/scripts/co-deck/tests/*.browser.mjs` are registered
   in co-deck's `SCRIPTS.md` as "runs via Node.js". The
   `theme-visual-regression.browser.mjs` row records the reason: bun has
   Playwright subprocess issues on Windows. This is a deliberate,
   already-documented exception.
3. **Browser/web assets.** `handbook` skill widget JS (dark-mode toggle,
   in-page search, etc., across platform mirrors), co-deck
   `docs/html-themes/` runtime JS, and the `co-design/playground/dist`
   bundle execute in browsers, not as workspace automation. ADR-0036's
   scope is operational automation scripts.
4. **Vestigial shebang.** `extract_slidedata.mjs` (co-deck) is documented
   and invoked as `bun scripts/co-deck/extract_slidedata.mjs` (pdf-export
   skill, co-deck SCRIPTS.md) but still carries its pre-migration
   `#!/usr/bin/env node` shebang.

## Decision

1. **graft shims and hook commands stay in graft's tool-owned node
   form.** bun can execute `.cjs`, but converting the settings commands
   buys nothing: graft regenerates the shims and wiring on upgrade and
   would revert the form. Treat graft-emitted node usage as compliant.
2. **co-deck Playwright browser tests may run via node** until the
   bun-Windows Playwright subprocess issue is resolved. The governing
   record is co-deck's `scripts/co-deck/SCRIPTS.md`; do not migrate these
   files to bun invocation without updating that record.
3. **Browser/web assets are out of ADR-0036 scope by definition.** The
   TS/bun standard applies to operational automation, not to frontend
   assets shipped to browsers.
4. **Vestigial node shebangs on bun-invoked, workspace-owned scripts are
   removed.** `extract_slidedata.mjs` loses its shebang (it is never
   executed directly); its bun invocation records are already correct.
5. **ADR-0036 remains the default.** New automation scripts must be
   single TypeScript files run via `bun`. This ADR only carves the
   exceptions listed above; any new node-runtime script requires a new
   decision record.

## Consequences

- Reviewers and audit passes read node usage in the four classes above
  as compliant, removing the false-violation signal.
- The exceptions are revisitable: if graft ships bun-native shims, or the
  bun-Windows Playwright subprocess issue is fixed upstream, this ADR
  should be narrowed or superseded.
- No code migration is performed for graft output — deliberately. The
  only code change under this ADR is the `extract_slidedata.mjs` shebang
  removal.
