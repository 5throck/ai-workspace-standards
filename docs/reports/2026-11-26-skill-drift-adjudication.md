## 1. Conclusion

Twenty-two in-scope pairs were classified; none is a genuine authoring divergence that loses work if resolved as recommended. Four pairs are intentional variant-override specializations that are already converged on disk (co-design design-stack ×2, co-safety review/lifecycle ×2); one pair carries a registered LOCAL-PATCH (project-review@co-abap, UR-2); one pair is a registered-shape path adaptation (project-review@co-work); two pairs are already converged with the template (accessibility-audit@co-design, meeting-facilitation@co-price — their "divergence" is other projects lagging the template, and a stale snapshot, respectively). Eight pairs need a small template-side port (2–11 lines each, mostly frontmatter/relates_to blocks and one repeated L0 note). Two pairs adopt the template with nothing substantive lost. Five pairs are cosmetic scaffold personalization (`<variant>` token rendered into `scripts/co-<slug>/` doc text) that no wave can ever heal and that a one-function hash-normalization fix would dissolve.

The 2026-11-23 verdict "delivery lag, not intent" still holds but the lag is **structural, not schedular**: the two 2026-11-26 waves ran clean and could not have healed a single one of these pairs. Three machinery causes produce the divergence classes (S1–S3 below, with file:line), and a fourth (S4) made the fresh fleet report itself undercount the fleet.

## 2. Method

- **P**: `Projects/<p>/skills/<name>/SKILL.md` on the project's checked-out branch (all clean on `main` at analysis time except co-price, on transient branch `pr/20261124-031753-fix-agents-regenerate-claude-agents-pm-m` — its file state is wave-current, see S4).
- **T**: the effective template source — `templates/<variant>/skills/<name>/SKILL.md` where a variant override exists (the VARIANT SKILLS lane, `upgrade-project.ts:7487`, runs after and shadows the common lane), else `templates/common/skills/<name>/SKILL.md` (common lane, `upgrade-project.ts:7152`). Both candidate T copies were hashed for every pair.
- **B**: the `baselines['skills/<name>/SKILL.md'].hash` in `Projects/<p>/.claude/last-upgrade-delivery.json` (both 2026-11-26 waves, templateVersion 0.30.0). **B was recoverable for only 2 of 22 pairs** (design-foundation@co-design 0.29.0, meeting-facilitation@co-price 0.30.0 — both equal P). The other 20 manifests carry NO baseline row for these paths: the SYNC_IF_NEWER equal-version arm delivers nothing and writes no baseline, which is itself evidence the waves never touched these files (corroborated by git: last P change predates both waves for all 20). Per the precedent's §3.1 fallback, those pairs were classified by direct P↔T comparison plus normalized-hash verification.
- **Classification rule**: TEMPLATE_SUPERSET when P's line multiset ⊆ T's; PROJECT_SUPERSET when T ⊆ P; TRUE_DIVERGENCE otherwise; EQUAL when the multisets match; **EQUAL-BUT-UNDELIVERED** when P equals T under the graph-hash normalization but the fleet report still shows a split. Diffs were re-read raw; every classification was cross-checked by recomputing the graph hash (`normalizeForHash`, `skill-graph-compat.ts:100-116`) of P and T and comparing against the 2026-11-26 snapshot hash groups and each project's own regenerated `docs/skill-graph.json`.

## 4. Systemic causes

**S1 — the SYNC_IF_NEWER version gate makes same-version template edits permanently unreachable** (`upgrade-project.ts:7238` `semverGt(tplVer, projVer)`; equal-version arm → CATCH-UP/DRIFT_PRESERVE `:7301-7331`, ADR-0085 D3; project-ahead arm → PROJECT_AHEAD skip `:7334-7343`; policy mapping `upgrade-policy.ts:895`). Two template commits landed content/stamp edits without version bumps: `bdb72db58` (2026-10-08, evidence-ledger overlay paragraph) and `d82a73649` (2026-11-08, "last_reviewed refresh x20" — which also restructured finishing-a-development-branch frontmatter and removed a blank line in accessibility-audit). Projects already AT the then-current version were cut off forever; projects one version behind received the edits in the 0.30.0 wave. That single asymmetry manufactured the minority groups for rows 1, 6, 7, 8 and the fleet-wide evidence-ledger lag. This is why two fully-delivered waves changed nothing here: **"delivered cleanly" is true at the CONFLICT level and false at the content level.**

**S2 — scaffold-time placeholder rendering forks delivered skills from their template source** (`helpers/substitute-placeholders.ts:53` replaces backtick-path `` `<variant>` `` tokens; CLI mode `:88-139` sweeps EVERY text file including `skills/**`; invoked whole-tree from `new-project.ts:1613`; contrast `create-l3-scaffold.ts:800-813`, which deliberately scopes rendering to docs/context.md only). Projects created via new-project carry personalized doc text the template never has; the version gate then treats the two as same-version drift forever. `normalizeForHash` (`skill-graph-compat.ts:100-116`) strips stamp lines but not the token, so the fleet report shows one hash group per variant — the script-lifecycle-manager sextet (rows 13–17) is entirely this. Only one of the 13 skills carries the token today, but any future `<variant>` usage in a common skill recreates the class.

**S3 — intent is not representable in the convergence classification** (report-side; `skill-graph-fleet-report.ts:327-362` `classifyConvergence` hashes normalized file content only). Variant-override specializations (rows 5, 11, 20, 21), registered LOCAL-PATCHes (row 10), deliberate path adaptations (row 12), and promotion relics (rows 4, 7, 18, 19) are all indistinguishable from drift. The engine knows pieces of this — `iterEffectiveTemplateFiles` variant-overlay resolution (`upgrade-policy.ts:965+`) and `markerLossBlocks` — but the fleet report consumes neither, nor any intentional-specialization registry; the i18n-audit@co-price exclusion was a hand ruling in a ticket, not a mechanism.

**S4 — the weekly snapshot silently drops mid-PR fleet members** (`filterTransientCheckouts` in `lib/git-aware-scan.ts`, called from `skill-graph-fleet-report.ts:1091-1100`): any Projects/co-* checkout on a `pr/*` branch is excluded. snapshot-2026-11-26 covers 14 projects; co-price (checked out on `pr/20261124-031753-fix-agents-regenerate-claude-agents-pm-m`) and co-architect are absent. The "fresh fleet report" the ticket reacts to therefore undercounted carriers and could not see 6 of the 22 pairs at all; the pair list under adjudication was carried forward from the 2026-11-23 analysis. Snapshot rows for absent members should be annotated (the history page already annotates transient PR checkouts elsewhere) rather than silently omitted.

**Verdict on the 11-23 ruling**: "delivery lag, not intent" holds — with one refinement. No project-side authored drift was found except the ci-triage L0 notes (rows 2–3), which are a *beneficial* shared fix that should be ported, and the co-architect promotion relics (rows 4, 7, 18, 19), whose intent was promotion normalization, not divergence. The rest is machinery: S1 (4 pairs + 1 fleet-wide lag), S2 (5 pairs), S3 (6 already-converged intentional pairs kept re-surfacing), S4 (report trust). A per-pair close-out alone would leave all four causes armed for the next snapshot.
