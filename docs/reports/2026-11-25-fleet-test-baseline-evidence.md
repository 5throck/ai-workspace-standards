## Fixes during verification (diagnosed at the root, not worked around)

1. `bun` writes its `N pass` / `N fail` report to **stderr** when stdout is piped, so the
   first count parser saw nothing (`tests=-1`). Fixed by parsing `stdout + "\n" + stderr`.
2. A step whose *discovered* files were all tagged for another platform failed closed.
   Fixed to key FC2 on discovered targets and print the `not applicable` lines (design
   implementation note 1).
3. `--plan-os` counted only applicable targets, so the linux leg reported `[]` for a
   windows-only repository. Fixed to count discovered tagged targets (note 2).
4. `test-runner.ts` imported `helpers/scaffold-markers.ts` eagerly; its import chain
   (`layer-filter.ts`, `lib/platforms.ts`, `lib/country-scoped-agents.ts`) does not exist
   in every project or any fixture, so `all`/`common` could not run from a bare runner.
   Loaded lazily for the `scripts` suite hygiene check only (note 3).
5. `validate-templates.ts` flagged the two L0/L1 twins as differing and the template
   runner as "content changed but version still 1.18.0" — the second is exactly the gate
   the version bump exists for. Both fixed by syncing the twins after the 1.19.0 bump.
6. `lifecycle-sync-audit.ts` Check H failed (`docs/lifecycle/scripts/test-runner.md`
   1.18.0 vs registry 1.19.0). Fixed by bumping the record with its phase-history row.
7. New test fixtures used `mkdtempSync(join(process.env.TEST_TEMP_DIR …))`, a **relative**
   base under the runner's `tests/.temp/worker-N`; the spawned battery/runner then resolved
   `cwd` relative to the child's own root and failed. Fixed by `resolve()`-ing the base —
   the same class as the Windows path bug the machinery PR fixed.
8. `ci-workflow-merge.test.ts` used `concurrency` as its example of a rejected unknown
   top-level key. Since v1.1.0 accepts it (the template now carries the block), the case
   moved to a genuinely unknown key and a new assertion pins that `concurrency` is accepted.

## Addendum — Windows CI failure on PR #2178 and the final CI state

The first push of this pull request failed `test (windows-latest, 18.x)` (run
45620792717) on `tests/unit/test-runner-os.test.ts > AC5 > --os-scope independent keeps
only untagged files` (`files=2`, expected 1). The root cause was in the runner, not in the
test: every selection site used `specific ? tag === os : tag === null || tag === os`, so on
a win32 host an **independent** run accepted the `.win32.test.ts` file, because its tag
equals the running platform. The darwin host masked it — the fixture tags win32. Left
unfixed, the fleet's OS-independent ubuntu leg would have been fine but any local Windows
`--os-scope independent` run (and the windows leg if it ever ran that scope) would have
dispatched OS-specific tests. Fixed in commit `f021d8a8f`-class change (see the branch's
`fix(test-runner): os-scope independent …` commit): the scope is explicit at all three
selection sites, and a platform-agnostic case (`--os win32 --os-scope independent`) now
pins it on every OS.
