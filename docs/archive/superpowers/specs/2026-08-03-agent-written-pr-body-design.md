# Design: Agent-Written PR Body (Remove `claude -p` Dependency)

- **Date**: 2026-08-03
- **Status**: Approved (awaiting implementation plan)
- **Scope**: Workspace root (L0) + common template (L1) propagation

## Problem

`scripts/gen-pr-body.ts` uses the `claude -p` CLI to generate AI PR bodies:

- Detection: `claude --version` at `gen-pr-body.ts:99`
- Generation: `$`claude -p ${prompt}`` at `gen-pr-body.ts:144`

This is a Claude Code–specific dependency inside a pipeline that is meant to be
platform-neutral. The workspace distributes skills/scripts to Claude Code, Gemini
CLI, and Antigravity (`.claude/`, `.gemini/`, `.agents/`), and hooks already
detect `--platform gemini`. Consequences:

1. On Gemini CLI / Antigravity environments, `claude` is not installed, so AI PR
   body generation silently degrades to the plain template fallback — violating
   platform parity.
2. When running inside a Claude Code session, `claude -p` spawns a nested
   non-interactive session, spending tokens twice for the same work.

## Decision

Remove the external LLM CLI invocation from the pipeline. The agent that invokes
`/sync` — whatever platform it runs on — writes the PR body itself. `dev-sync.ts`
accepts that body via a temp file and submits it with `gh pr create --body-file`.
If no body is provided, the existing fallback chain remains unchanged.

## Data Flow (after)

```
/sync "feat: description"
  │
  ├─ [sync skill] Agent writes PR body itself
  │     git diff HEAD~1 inspection → fixed structure (English)
  │     → saved to <git-dir>/sync-pr-body.md (outside working tree, never committed)
  │       where <git-dir> = `git rev-parse --git-dir` (handles worktrees/submodules)
  │
  └─ bun scripts/dev-sync.ts --body-file <git-dir>/sync-pr-body.md "feat: description"
        ├─ body file present → language validation → gh pr create --body-file
        ├─ else gen-pr-body.ts (template)      → gh pr create --body
        ├─ else .github/pull_request_template.md → gh pr create --body
        └─ else gh pr create --fill            (existing fallback chain)
```

## Changes by File

| File | Change |
|------|--------|
| `scripts/gen-pr-body.ts` (+ L1 copy in `templates/common/scripts/`) | Remove Claude detection (`:99`) and AI mode (`:98-161`). Keep language validation + template fallback generation. Version `1.1.5 → 1.2.0`. |
| `scripts/dev-sync.ts` | Support `--body-file <path>` argument. When present, read the file, validate English via `hasNonEnglish` (already imported at `dev-sync.ts:7`), and use `gh pr create --body-file` (avoids shell-escaping issues with large bodies). Version `1.3.6 → 1.4.0`. |
| `skills/sync/SKILL.md` (+ platform-synced copies in `.claude/skills/`, `.gemini/skills/`, `.agents/skills/`) | Add step: agent writes the PR body using the fixed structure (Why / What Changed / Test Plan / Security Checklist / Notes) and saves it to `<git-dir>/sync-pr-body.md`, then passes `--body-file` to dev-sync. Keep the English-only PR rule. Version `1.1.0 → 1.2.0`. |
| `scripts/SCRIPTS.md` | Update `gen-pr-body.ts` purpose text (remove AI-mode wording). `scripts/README.md` is regenerated by the pipeline automatically. |

## Edge Cases

- **No agent-written body** → existing fallback chain works unchanged
  (`gen-pr-body.ts` template → `pull_request_template.md` → `gh pr create --fill`).
- **Non-English agent body** → blocked by the same `language-guard` gate used
  for the commit message, consistent with existing behavior.
- **Standalone invocation** `bun run gen-pr-body "msg"` → still works, template-only.
- **Existing-PR idempotency** (`dev-sync.ts:406` `gh pr view`) → unchanged.

## Scope / Propagation

- L0 → L1 (`templates/common/scripts/*`, `.claude/skills/*`, `.gemini/skills/*`)
  propagation happens automatically via dev-sync step 4.7 (`propagate-to-templates.ts --apply`).
- **L2 variant projects** (co-architect, co-consult, co-deck, co-game, safety_os)
  still carry the old `gen-pr-body.ts` with `claude -p`. Syncing those is a
  separate, explicitly requested follow-up — out of scope for this change.
- `gen-pr-body.ts` is a registered public script interface (SCRIPTS.md), so it is
  **kept** (template-only) rather than deleted — minimal-change principle.

## Verification

- Existing fallback paths (`--fill`, `pull_request_template.md`) remain intact.
- These scripts currently have no unit tests; the `--body-file` handling is a
  simple branch inside `dev-sync.ts`, so no new test file is added.
- Manual check: `/sync` on a non-Claude platform produces the same structured
  body as before.
