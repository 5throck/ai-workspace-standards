## Decision context

The hand compiler reached "every local oracle green, PowerPoint still
repairs" eight times. The environment cannot generate the missing oracle
(no Office tooling by policy), so the knowledge had to come from a
battle-tested external implementation. The user probe-verified the spike
PPTX in real PowerPoint (2026-11-07, no repair prompts), which was the
pre-gate condition of the design; Phase 1 (adapter + emit via their chain)
proceeds under this record.

## Conditions attached

1. Their chain is consumed verbatim — no ppt-master file is ever modified
   in the pinned clone; the clone is read-only by convention.
2. Only their deterministic scripts are wired; their LLM/agent authoring
   stages are never invoked.
3. MIT attribution (repo + license) appears in the pptx-export skill doc;
   upstream LICENSE/copyright files in the clone are never stripped.
4. PyMuPDF/AGPL stays out of every install list and dependency surface.
5. The svg-check fingerprint discipline remains OUR internal content gate;
   it is not a PowerPoint-validity claim.
6. Supersession is scoped: the 2026-11-03 spec's authoring/gate tiers stay
   in force; only its compile/export tier is superseded.
