## Ruling

1. **Approval basis.** The user instructed "T-20261026-001 처리해줘"
   (2026-10-26). The only self-contained plan on record for that urgent
   ticket is the registered remediation design
   `2026-10-26-project-review-remediation-design`, whose §10 names Option
   (b) refined as recommended and leaves Option (a) to explicit user
   preference. Processing the ticket therefore constitutes approval of
   Option (b) refined; Design Gate Row 0 is satisfied by the registered
   design, whose status moves proposed → approved (recorded here and on the
   design's Status line). The user may still amend before merge.
2. **Authorized scope.** Deliver `lib/platform-skeleton-merge.ts` as
   `L0+L1` (the leaf-pure-module class, per the `lib/upgrade-policy.ts`
   precedent); return `upgrade-project.ts` to `L0` per ADR-0073 Amendment 3
   and delete the L1 engine mirror; retire the 16 inert project engine
   copies via the standing `--prune-removed` path (one-project canary
   co-develop first, the remaining 15 via the nightly wave); record ADR-0073
   Amendment 4 as a correction of record; land the `l1-import-closure`
   ratchet (ticket T-20261026-011) so the class cannot silently return.
3. **Landing choice.** The remediation lands in the same PR as the review
   (#1609): that branch is unmerged and CONSTITUTION §3.3 forbids parallel
   unmerged branches — a separate PR would conflict on the ticket YAML and
   the spec registry. Alternatives (a) and (c) are rejected as recorded in
   the frontmatter.
4. **Release hold.** Template release v0.20.2 stays on hold (no
   `auto-release-template.ts --release`, `release-template.ts`, or
   `tag-template.ts`) until the design §6 acceptance battery is green; the
   D2 delete + D1 add then classify the next cut as a MINOR carrying the
   fix, not the break (design §7).
