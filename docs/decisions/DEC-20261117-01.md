decision: >-
  Gate-moment design amendment (Amendment B) to
  2026-11-16-co-deck-pdf-html-backport-design.md section 4.2, ruled before the
  PR-2 QA gate. Deviation (automation-engineer): the design's section 4.2
  item 1 specified the zen template contact branch render bullets
  append-always ("after the contact* items"), while item 2 always specified a
  fallback-only contract for the PDF renderer; the engineer implemented
  fallback-only on the HTML side (zen/template.html contact branch gates on
  !hasContactLine over contactEmail/contactLinkedIn/contactPhone) to mirror
  the PDF's contact*-first contract (gen-slides-pdf.ts:1625-1636, bullets
  only when cLines.length === 0, first fallback line bold via primaryFirst).
  VERIFIED by architect: both landed/in-flight implementations are
  fallback-only and shape-compatible (max 5 lines, first line
  .contact-primary / bold card ink). RULING: the deviation is ACCEPTED as
  the contract — option (a). The contract is single-sourced as "bullets
  render iff no contact* line resolved", implemented identically in both
  outputs. Rationale: (1) parity is the work item's stated goal (section 10
  U-008-contact row, section 13) and one testable rule beats two divergent
  ones; (2) output-neutrality, the Amendment A principle — append-always
  would change output for pre-existing decks carrying bullets beside
  contact* fields (previously invisible bullets become visible), while
  fallback-only changes only the bullets-only case, which is the defect
  being fixed (S47); (3) the deck-proven shape is preserved exactly — S47
  carries no contact* fields and renders identically under either contract.
  Known parity edge RECORDED NOT FIXED: a slide carrying BOTH contactName
  and bullets diverges (the PDF known list includes contactName so it
  renders the name and suppresses bullets; the zen template has never
  rendered contactName at all, so it renders the bullets) — redundant
  authoring, never in parity pre-batch, and closure would need a template
  contactName-rendering change outside this batch's scope; decks wanting
  both lines author bullets only. Design doc section 4.2 item 1 amended
  (Amendment B), section 4.3 gains the mixed-fixture parity pin, section 4.4
  R-D1 narrowed, section 13 gains the fallback-only acceptance bullet,
  header status line updated. ENGINEER INSTRUCTION: NONE — the in-flight
  implementation already matches the ruling; no template/script/test change
  is required. Proceed to the PR-2 QA gate. Follow-up ticket candidate (not
  filed by this ruling): template-side contactName rendering for full
  contact-field parity.
alternatives: >-
  (append-always on the HTML side per the original item 1 wording, REJECTED)
  breaks HTML/PDF parity for mixed decks by construction, contradicts the
  section 10/13 parity statements, and mutates output for pre-existing
  contact*-with-bullets decks against the output-neutrality principle;
  (append-always on BOTH sides, REJECTED) would also force a PDF change
  after PR-1 landed and widen the output diff beyond the defect; (close the
  contactName edge in this batch, NOT TAKEN) out of scope — no ticket
  claims it and it needs its own design pass.
