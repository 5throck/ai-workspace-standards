## Decision context

U-20261028-002 (done, local-only) documented the instance: co-newbiz's
project-local persona script silently strips `model:` from all its
`.claude/agents/` mirrors after ADR-0102 flattened the SSOT tier shape, and
its drift check cannot catch real divergence. U-20261028-003 (waiting,
owner-requested) names the systemic gap: platform rules — which surfaces
support agent definitions, which fields they accept, which model identifier
they want — live in unmanaged per-project code and nowhere else. PM
verification plus this session's re-verification established: no
workspace-level agent-mirror machinery exists (no `templates/common/.claude/agents`,
no logic in sync-skills.ts or sync-variant-settings.ts); 146 template agent
files still carry `model: inherit` beside flat `tier:`; co-newbiz is the
only one of the 16 fleet projects with a mirror tree (41 mirrors); no
consumer requires the frontmatter `model:` field; and the in-tree platform
evidence supports exactly one file-based agents surface (Claude Code) with
Codex explicitly subagent-less (CODEX.md:144) and Gemini CLI subagents
defined at runtime (`define_subagent`/`invoke_subagent`), not files. This
record fixes the disposition so the implementing specialists
(automation-engineer, docs-writer) execute against a settled contract; the
design doc carries the full registry schema, generator I/O, gate semantics,
sweep scope, rollout order, and validation plan. The decision is ACCEPTED —
the user approved the design on 2026-10-28 (owner confirmation `진행`),
adopting all five §9 recommended defaults (Q1 Claude-only mirrors, Q2 standalone
generator with a dev-sync --check step, Q3 blocking day-one severity, Q4
co-newbiz domain-sync carve-out, Q5 registry in workspace-schema.json) as the
implementation contract; PR-1 (root scope, §6 step 1) dispatched to
automation-engineer the same day.

## Conditions attached

1. No implementation before user approval of Q1–Q5; this record's defaults
   (Claude-only mirrors, standalone generator with dev-sync `--check`
   step, blocking day-one severity, co-newbiz domain-sync carve-out,
   registry in workspace-schema.json) become the contract on approval.
2. The registry↔adapter coverage guard lands in the same PR as the
   registry block and generator — a registry without its guard is the
   U-002 class reopened.
3. The `model:` sweep is transform-only and enumerated at execution time
   (grep-verified set, never a hardcoded list); L1/L2 files get version
   bumps in the same change so redelivery is guaranteed; the two orphan
   projects converge via the local one-shot pass, never left to the WARN
   net.
4. co-newbiz's `sync-agent-personas.ts` is deleted only after the
   delivered generator is installed locally, has adopted the 41 existing
   mirrors into the provenance manifest, regenerated them, and passed
   `--check` plus the full audit — and only the persona half; the ADR-0153
   domain-sync function is dispositioned separately (Q4) before deletion.
5. Upgrade never auto-writes mirror trees fleet-wide; each project's first
   generation is one deliberate, diff-reviewable run, and the blocking
   gate — not the upgrade — is the enforcement point thereafter.
