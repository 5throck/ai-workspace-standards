## Context

On 2026-11-28 the architect produced the external-LLM configuration design
(docs/designs/2026-11-28-external-llm-config-design.md) analyzing which
external dependencies need LLM configuration. The survey found the need
latent — humanize's consumed surface is a deterministic offline rules engine
with zero LLM calls — and recommended Option B: a gitignored, project-level
`external-config/<id>.env` file declared by an optional manifest `config`
block, materialized into the clone as a symlink, with a value-blind compat
gate check (V11). The design carried six open questions for the owner
(OQ1-OQ6, §13) and was left untracked with `Status: draft (untracked, for PM
review)`.

Evidence. The owner reviewed the design and confirmed approval on
2026-11-29, adopting OQ1-OQ6 to the design's recommendations and ruling that
implementation is deferred to service ticket T-20261129-001 (backlog). The
approval is the owner's only act recorded here; the landing itself (branch
`docs/external-llm-config-approval`) is executed by the automation-engineer
at the PM's dispatch.

## Decision

The approval in the frontmatter is recorded as the ruling.

Scope limits. This decision does NOT approve:

- Any implementation work. `scripts/lib/external-deps.ts`,
  `scripts/external-deps.ts`, `scripts/upgrade-project.ts`,
  `scripts/contained-run.ts`, the humanize adapters, the template seeds, and
  the context docs are all untouched — the whole surface belongs to
  T-20261129-001.
- Any wiring of an LLM mode (OQ1: wire nothing). The first real consumer
  arrives with its own spec through the normal Design Gate.
- Any change to the co-newbiz humanize pin (OQ5: out of scope).
- A new ADR for the two-layer key split (OQ6: cross-reference paragraph
  only, when the rollout PRs land).

The landing set is exactly: the design doc (header `Status` amended to
approved, one dated 2026-11-29 amendment line, content otherwise verbatim),
the new spec-registry entry `2026-11-28-external-llm-config-design` (status
`approved`, source `manual`), `docs/specs/registry.json` (regenerated
projection), this decision record, and the pipeline bookkeeping (memory log,
VERSION_MANIFEST, CHANGELOG entry). All paths are outside the ADR-0105
protected-path class, so the landing PR merges on real CI green.

## Consequences

- The design is tracked, registered, and auditable; the spec-check gate no
  longer sees it as untracked draft material.
- T-20261129-001 remains in backlog as the single pointer to the held
  implementation. Nothing schedules it; the owner drives it.
- The registry entry's status advances to `implemented` only when the
  T-20261129-001 delivery lands (via the normal `--update` flow at that
  time).
- The OQ rulings bind the future implementation: a later implementer cannot
  re-litigate symlink-vs-copy, gate depth, directory name, or scope without
  a new owner ruling.
- No runtime behavior changes anywhere in the fleet from this landing.
