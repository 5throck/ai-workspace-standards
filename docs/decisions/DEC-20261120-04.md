## Context

T-20261112-003 closed as done with the manifest landed but no verifier created;
meeting 2026-11-20 confirmed "Not live" / "Committed != ratified". The Design Gate
verification for this cluster found the gap LIVE: the automation store's prompt
(sha256 c91eeb1c…, 22,153 bytes) differs from the ratified manifest hash (e50d661f…,
21,872 bytes) in five hunks — the store text is ahead of the committed record. The
watchdog precedent (launchd, host state, out-of-process) is the workspace's proven
pattern for controls the runner cannot silence.

## Decision

As recorded in the frontmatter: launchd-scheduled verifier as the control of record;
manifest doc amended; bun:sqlite byte-exact reads; five verdict classes; STEP 0
--gate as defense-in-depth; allow-exec closure check; ZCode automation demoted to
fallback. Full design: `docs/designs/2026-11-20-runner-hardening-integrity-design.md`
§3.3. Prerequisite: the current drift is reconciled first (ratify the live text as
v5 or roll back — owner call, design §3.3.3d), then the verifier arms.

Status note (2026-11-20, PR 1): the launchd default (design §11 open question 2) is
operative under the same standing owner-delegation disposition; this DEC remains
proposed until the verifier script and the host plist land (PR 2), which is when its
closure evidence is recorded.

## Consequences

As recorded in the frontmatter. Governing surfaces: the new verifier script, the
launchd plist (operator-managed host state), `prompts.manifest.json` doc wording,
the v5 prompt STEP 0 line, and `docs/runner-exec-allowlist.json`.
