## Decision context

The 2026-11-04 incident (a PM agent ran `rm -rf Projects` at the workspace
root; 16 L2 checkouts lost, all recovered — memory/2026-11-04.md lines
159–181) produced the project-loss hardening design at the Design Gate
(Row 0), filed under the re-created governing ticket T-20261104-004. The
design's §11 carried four open questions requiring an explicit user ruling
before implementation: the 16-variant §7 prose wave exceeds the architect's
3-template-file high-risk threshold; the Gemini gated-decision mapping;
whether `git clean` / `find -delete` belong in v1; and the surface of the
duplicate-refusal override. On 2026-11-05 the user ruled on all four via
structured questions and approved the design itself.

## Ruling

1. **Design approved** — all four hardening items proceed (delete-guard hook,
   `Projects/` test isolation fix, ticket-store durability, governance prose).
2. **§7 prose scope: full wave now** — root AGENTS.md +
   templates/common/AGENTS.md + all 16 variant AGENTS.md + HERMES.md in one
   PR, with the new validate-templates WARN arm pinning the marker phrase;
   the 16-file high-risk threshold is accepted for this wave (single phrase,
   machine-pinned).
3. **Gemini delete-guard mode: `deny`** — its Manual terminal approval already
   supplies the human confirmation; deny is the stronger default.
4. **v1 pattern scope: `rm`/trash recursive deletes only** — `git clean` /
   `find -delete` variants deferred to v2 (accepted false-positive-reduction
   rationale).
5. **Duplicate tickets: store-level refusal** — exact normalized-title match
   across both stores, with a CLI `--allow-duplicate` override approved.
