## Context

On 2026-11-26 evening, the /sync of the root 4-path scope (@types/bun
^1.4.5 bump, session log, U-20261126-003.yaml) FATAL-failed at dev-sync
step 3.87 (ticket-store memory-drift, design
`docs/designs/2026-11-04-project-loss-hardening-design.md` §5.3b): 10
ticket ids cited in `memory/2026-11-26.md` (T-20261126-001, -002, -003,
-004, -006, -007, -008, and T-20261125-002, -003, -004) resolve in no
store or archive.

Evidence. Automation-engineer field report, 2026-11-26:

- The 10 yaml files were created working-tree-only by earlier sessions
  and never committed: `git log --all` on those paths is empty. The
  nightly closeout PR #2190 (commit `aed2b08d5`) touched zero `tickets/`
  files despite its session block listing `T-20261126-001.yaml`.
- The files were present at the #2190 sync (that run passed step 3.87)
  and vanished from the working tree afterwards; the deletor is
  unidentified.
- Not in the `tickets/governance/` live store (only T-20261125-001
  remains for Nov 25-26), not in `tickets/governance/archive/`, and there
  is no `tickets/archive/` directory.
- The nightly "orphan sweep" is ruled out as the deletor: reports show it
  is agent-roster orphan reporting (trail, skill-graph-analyst), writing
  snapshot artifacts only.
- The gate has no exemption mechanism. Its two prescribed remedies are
  restore-the-file or correct-the-citation. Correcting citations in
  already-landed memory records would falsify the audit trail - rejected.

## Decision

The adjudication in the frontmatter is recorded as the ruling. This is a
PM gate-moment decision record under ADR-0061; the record was written by
docs-writer at the PM's dispatch.

1. Remedy = restore, via reconstruction. Recreate the 10 ticket files
   under their ORIGINAL ids (citations must resolve). Fields
   (title/status/kind) are derived strictly from `memory/2026-11-26.md`
   session records and today's daily reports. Every reconstructed file
   carries an explicit provenance note: "reconstructed 2026-11-26 from
   session records; original working-tree-only file never committed and
   lost; adjudicated under DEC-20261126-001". Statuses are kept at best
   evidence, with the inference noted where ambiguous.
2. File a NEW incident ticket via `bun scripts/ticket.ts` documenting the
   loss (working-tree-only governance records + suspected scoped-staging
   drop of protected `tickets/` paths in closeout PR #2190), so the root
   cause is tracked in the store itself.
3. Landing proceeds through the normal /sync pipeline (spec exemptions
   E1/E3 for the original scope), with the reconstructed tickets riding
   the same pull request so the store and its citations re-enter git
   together.

Scope limits. This decision does NOT authorize editing any historical
memory text, and does not adjudicate the root cause of the loss - that is
the incident ticket's follow-up work.

## Consequences

- Step 3.87 resolves on the next run.
- The store regains truthful, provenance-marked records for the 10
  citations.
- The loss incident gets a tracked follow-up: investigate why the
  closeout sync dropped protected `tickets/` paths it listed.
- No historical memory text is altered.
- Risk accepted: inferred statuses may be imperfect - mitigated by the
  provenance note on every reconstructed file.
