## Appended entry (2026-11-17, gate-moment): T-002 wrapper-flow reset accepted into PR-4 scope

- **Ruling**: ACCEPTED as specified. The section 1.2 chrome-hide denylist alone does not achieve the section 1.3 invariant (page count == slide count) on ppt-engine runtime decks; the wrapper-flow reset joins T-002's fix scope — same file (`html-to-pdf.ts`), same mechanism block (the injected print-CSS). Exact addition: `.ppt-main, .presentation-container { display: block !important; overflow: visible !important; height: auto !important; flex: none !important; padding: 0 !important; }`.
- **Verified mechanism** (architect, against main's source of truth): ppt-engine.css's `@media print` block (:728+) resets `.ppt-main` only partially (flex/height/overflow at :735-738) leaving its base `display: flex` (:32) intact, and never touches `.presentation-container` (base :37-43: `flex: 1; display: flex; align-items: center; justify-content: center; padding: 1.5rem`). Consequence: the wrapper pair stays a flex/centering/padded context around the engine's per-slide print rules — the stacked slide flow is horizontally flexed, misaligned against page boundaries, and clipped/pushed into empty pages via `break-inside: avoid`. **Attribution correction to the engineer's report**: `overflow: hidden` lives on `.ppt-main`'s base rule (:33) and IS reset by the print block there; the residual culprits are the un-reset `display: flex` on both wrappers and `.presentation-container`'s untouched flex/centering/padding.
- **Rationale**: same symptom class (pages ≠ slides) as T-002; same injected print-CSS mechanism block, so no new file or mechanism; zero legacy-deck impact — legacy `<section>` decks and non-ppt-engine decks lack both classes (selectors are no-ops; outlook/vertical templates carry neither wrapper), pinned by Fixture C.
- **Verification scope**: the landed diff was not visible in any git state reachable at ruling time (branch `pr/20261117-co-deck-pdf-followups-pr4` tip carried no html-to-pdf changes; working tree clean) — this ruling verifies the MECHANISM and accepts the described fix shape. The QA gate must pin the actual landed diff: `html-to-pdf.ts` @1.3.1, both wrapper selectors plus the §1.2 denylist present in the injected block, and the minimal-fixture measured pdf-lib page-count pin (3-slide zen fixture == 3 pages). Engineer's battery (362 pass / 2 pre-existing; html-to-pdf suite 16/16 with measured page-count pins) is re-run at QA against the landed diff.
- **Design doc**: §1.2 amended (T-002 Addendum, 2026-11-17) and §10 acceptance bullet added — both cite this DEC (DEC-20261117-04, appended entry).
- **Disposition**: PM may proceed to the PR-4 QA gate. Candidate follow-up (not a PR-4 dependency): upstream polish of ppt-engine.css's own `@media print` wrapper reset so older deck-linked engine copies stop depending on the render-side injected block.
