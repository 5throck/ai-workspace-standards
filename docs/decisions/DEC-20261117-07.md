## Context

Lifecycle PR-4 (T-20261116-003 phase 1b, design
[2026-11-17-template-lifecycle-batch-design.md](../designs/2026-11-17-template-lifecycle-batch-design.md)
§5.3) mechanically re-syncs the 95 frontmatter-only shadow instances to common
bytes. The design's acceptance (§8) is residual 129 + mirror TRACE mv=cv +
skill-graph green — deliberately no version-bump language, because §5.5 declares
the reset of variant frontmatter to common's "intended (the mirrors are
distribution copies, not independent records)".

Implementation surfaced a collision the design did not anticipate: CV-02
(`same-version-content-change`, v1.78.0 / DEC-20261111-01, blocking, "no
exemption") FAILs any modified `templates/**` versioned file whose bytes changed
while the extracted version is unchanged. The 95 converged copies trip it 87
times (8 candidates are out of CV-02's universe: 6 whose version legitimately
changed, 2 command copies with no extractable version). Bumping versions to
satisfy CV-02 would break the design's own mv=cv acceptance.

The architect (Design Gate reviewer for this collision) was unavailable — model
quota until 18:55. The user instructed the PM to finish PR-4 this session, so
the PM ruled directly.

## Decision

CV-02 gains a convergence exemption as recorded in the frontmatter: a candidate
whose working-tree bytes equal its `templates/common/<rel>` twin is exempt and
reported; absent/divergent twins keep failing. The pure core is extended without
weakening existing semantics — `findSameVersionContentChanges` is untouched and
the classification lives in a new pure helper.

## Consequences

As recorded in the frontmatter. Version taxonomy: `validate-templates.ts`
1.84.0 now carries the exemption; the zone-override work reserved for 1.84.0 in
design §7 PR-5 takes **1.85.0**.
