  Gate-moment ruling (Design Gate, PM Row 0) on the external-deps drift
  workflow defect (T-20261107-006 reopen). EVIDENCE: the weekly workflow
  (.github/workflows/external-deps-drift.yml, Mondays 03:30 UTC) scans
  Projects/*/external-deps.json, a path that does not exist in the CI checkout
  (.gitignore:10 `/*/` — all project subdirectories are independent git repos,
  documented at .gitignore:2-4); every scheduled run since creation has failed
  (10-19, 10-26, 11-02, 11-09, 11-16, ~8s each, jq exit 2 on the literal glob)
  and the workflow has never once succeeded. Its ticket was closed as done on
  2026-11-08 with "real CI green" evidence that does not survive the run
  history — the closure is void. RULING: option (d), hybrid. (1) The CI scan
  is repointed to the tracked template seeds (templates/*/external-deps.json —
  common empty, co-work 3 entries, co-deck 1 entry), reusing the existing
  `bun scripts/external-deps.ts check-updates` machinery (setup-bun v2.2.0
  SHA-pinned step; findings from [UPDATE] rows only — the CLI's isNewerTag
  replaces the old raw string-inequality comparison; issue title becomes
  "[templates] external-deps seed pins drifted from upstream releases").
  (2) Project-side pin drift is covered by a documented local sweep in the PM
  Weekly Health Check (CONSTITUTION §9.1): `for d in Projects/*/; do bun
  scripts/external-deps.ts check-updates --project "$d"; done` (report-only,
  exit 0). Rationale: the original acceptance ("scan every project's pins")
  is impossible in CI — the co-* projects are private sibling repos, GITHUB_TOKEN
  cannot read them without a PAT, and private-repo Actions minutes are under a
  billing block (T-20261110-008) — while seed pins are the propagation source
  (upgrade passes take seed fields by id; scaffolds inherit seeds), so seed
  drift is the decision-relevant CI signal; retiring the workflow (option c)
  would discard the accepted R4 ruling and the automatic-issue path for zero
  gain; cloning siblings (option b) adds a PAT credential surface and stays
  non-functional under the billing block for a signal-only scan. Option (a)
  alone was insufficient because it silently narrows the promised project-side
  scope without documenting the compensation. TICKET DISPOSITION: reopen
  T-20261107-006 (move to review), amend acceptance to the CI-satisfiable
  scope (green scheduled/dispatched runs over seeds; sweep documented in
  CONSTITUTION §9.1), re-close only on a real green run's evidence. Design:
  docs/designs/2026-11-17-external-deps-drift-workflow-fix-design.md
  (registered spec 2026-11-17-external-deps-drift-workflow-fix-design).
  ENGINEER INSTRUCTION: rewrite the scan step of
  .github/workflows/external-deps-drift.yml per design §6.1 (repoint glob to
  templates/, add setup-bun step, aggregate via check-updates output, retitle
  the issue) plus the one-sentence CONSTITUTION §9.1 sweep row per §6.2;
  cli-version-drift.yml is explicitly OUT of scope (its 2026-11-16 failure was
  by-design drift signal, resolved by PRs #2048/#2049). Never bumps a pin —
  signal-only posture unchanged.
alternatives: >-
  (a) repoint to seeds only, REJECTED as insufficient: loses project-side pin
  signal with no documented compensation, though it is the correct CI-side
  core and is absorbed into the ruling; (b) clone sibling private repos in CI,
  REJECTED: needs a PAT secret for a signal-only scan, GITHUB_TOKEN cannot
  read siblings, and the private-repo minutes billing block (T-20261110-008)
  makes the job non-functional today regardless of credentials; (c) retire the
  scheduled workflow and rely solely on the local Weekly Health Check sweep,
  REJECTED: contradicts the accepted R4 ruling (a scheduled root-side,
  issue-opening scan), gives up automatic issue creation to PM discipline, and
  discards a landed artifact that is one path change from working.
