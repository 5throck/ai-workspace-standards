decision: >-
  Design Gate rulings (ADR-0061 record) for
  docs/designs/2026-11-11-upgrade-overwrite-protection-design.md,
  the remedy design for the template-overwrite fleet audit
  (docs/reports/2026-11-11-template-overwrite-fleet-audit.md,
  audit §7 questions 1, 2, 3 and 5). Provenance: the user
  answered the audit's decision questions explicitly on
  2026-11-11 and marked the answers final; the PM dispatched
  the architect with these decisions as fixed inputs. Four
  rulings. (1) The DEC-20261110-04 non-goal "no change to the
  disposition matrix for PROJECT_EVOLVED" is REVERSED (this
  amends DEC-20261110-04 ruling 2 and answers open question Q4
  of the delivery-gating-hardening design): the engine
  delivers a template copy over project evolution only when
  the template content changed since the recorded baseline; a
  project-only change records the new verdict EVOLVED_PRESERVE
  (WARN), the project copy is preserved and the baseline is
  kept; an explicit per-path grant (adopt-template, or a
  backport ack) is the only restore path. (2) The backport gate
  BLOCKS: rollout off -> shadow -> enforce; in enforce, an
  upgrade apply whose gate set (project-ahead and
  pendingBackport paths, including EVOLVED_PRESERVE,
  non-vintage unbaselined divergence, marker loss and
  project-evolved CONFLICT) lacks a fresh per-path verdict
  requires --backport-ack and is refused before any write
  otherwise; the gate lives in the engine so off-cycle and
  targeted deliveries are covered too. (3) Apply runs are
  FROZEN for Projects/co-deck, co-abap, co-hr, co-safety and
  co-newbiz until the engine change lands (design PR-A and
  PR-B merged, fleet dry-run sweep reviewed, co-deck canary
  passed); dry runs stay allowed. (4) Every LOCAL-PATCH form
  counts as protective - upstream-request:, design:,
  project-local and the bare LOCAL-PATCH U-<id> form - and a
  marker-loss guard compares LOCAL-PATCH marker counts on
  every delivery path (version- and hash-gated deliveries,
  equal-version restore, core-locked restore, ci.yml MERGE,
  DOCS_MERGE and instruction-file MERGE, docs/context.md
  region splices, JSON merges, prune, platform skill mirrors);
  a count decrease without a grant is MARKER_LOSS (ERROR) and
  the write is skipped. The design also adopts the audit
  remedies P1-P3 as phased work (equal-version restore only on
  baseline- or vintage-proven provenance, PROJECT_AHEAD verdict
  and manifest pendingBackport[], destructive-WARN landing
  acknowledgement at dev-sync step 3.9, validate-templates
  CV-02 same-version content change, the cdf316143 noise
  handled by a provenance suppress rule instead of a baseline
  reset, three-way merge for docs/yaml/css behind a flag) and
  the upgrade-project 1.7.0 / project-resync 1.9.0 skill
  changes. Implementation tickets are not yet created; they
  land after the open PR1/PR3/PR4 (T-20261110-009/-012 engine
  work).
