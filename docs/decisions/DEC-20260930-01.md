## Ruling

1. **Port**: apply the three validator fixes to `scripts/` and
   `templates/common/scripts/` per the design note. Tests go to
   `tests/unit/script-registry-audit.test.ts`.
2. **Check 11**: option (b). When Check 11 finds the last commit date newer than
   `last_updated`, it uses the date of the last commit that is not a sync-only
   commit. A sync-only commit matches the pipeline subjects
   `chore(upgrade): template sync ...` (and equivalent propagate subjects).
   Suggested implementation: `git log -1 --format=%cs --invert-grep --grep=<pattern> -- <file>`.
3. **Delivery**: not in this PR. The change needs a shared subject pattern that
   stays in step with `upgrade-project` / `propagate` / `dev-sync` commit messages,
   plus tests with git fixtures. Open a follow-up ticket (owner: automation-engineer).
4. **Fleet**: new warnings keep their existing severity and do not block.
   Default: each L3 project backfills on its next upgrade. The human chooses
   the final absorption mode (see design R6).

## ADR assessment

No ADR required. The changes are bug-fix/minor versions of existing validators;
no check changes severity, no schema, auth, or gate semantics change, and Check 11
stays at warn level. Reassess if the follow-up promotes Check 11 to error or adds
a new commit-message contract that other pipelines must follow.

## Consequences

- Validators find agents that co-newbiz-style rosters were hiding; L3 projects see
  more warnings after the next upgrade.
- Check 11 stays noisy until the follow-up ticket lands.

## Amendment (2026-10-03)

Ruling 2 excluded only sync-only commits (agent-lifecycle-audit 1.5.0). That left a self-referential flaw: a commit that only bumps the `last_updated:` frontmatter line (for example 6b2074be, 2026-10-02) is itself a content commit, so the bumped value is immediately older than the file's last commit. Result: 8 permanent Check 11 WARNs (auditor, automation-engineer, architect, security-expert, skill-graph-analyst, lifecycle-manager, docs-writer, scaffolding-expert).

Amendment to ruling 2: agent-lifecycle-audit 1.7.0 also skips metadata-only commits, defined as commits whose diff for the file changes only the `last_updated:` line (diff headers are ignored only before the first hunk; any other changed line, an empty diff, or any git error counts as content, so real staleness is never hidden). Check 11 stays at warn level, so the ADR assessment above is unchanged (no severity, schema, or gate-semantics change).

References: `docs/designs/2026-10-03-validator-warning-fixes-design.md`; PR #1340 (merged 2026-10-03).
