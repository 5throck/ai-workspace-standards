## Decision context

The user asked for an analysis of the ppt-master workflow and a design for
reflecting it in the workspace's co-* templates. Across five planning rounds
the scope converged: first co-deck placement (three-pipeline), then a
rename-scope question (D-Stage naming), then an integration-architecture
requirement (avoid D/P divergence, link ppt-engine themes), then a promoted
SVG direct-authoring path, and finally the structural simplification: keep
co-deck at its current level and land the capability in co-work instead. Each
round's rejected shape is preserved in `alternatives` so the implementation
round does not re-litigate them.

## Conditions attached

1. Implementation starts only after the user approves the design doc (Design
   Gate Row 0 approval) and is dispatched as its own execution plan.
2. The canonical SVG authoring language stays a closed whitelist; widening it
   requires a spec update, not per-run improvisation.
3. No attribution or license notice for ppt-master appears anywhere (clean-room
   ruling); if a future round ever vendors external code, that decision gets
   its own gate-moment record.
