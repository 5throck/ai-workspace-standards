## Decision context

The T-20261103-002 implementation (PR #1835) extended
checkHubDoctrineDuplication so that a variant-identity registry row sanctions
a same-named local copy. co-architect and co-price then passed their
preflight legs. co-abap still failed three rows: architect, code-writer and
test-runner are present under templates/co-abap/agents/ with names that
co-develop's hub-doctrine rows also carry, and no co-abap registry row
sanctioned them. The implementation pinned the residual deliberately (the
pin asserts exactly those three fails and cites this ticket) so the gap
could not silently grow, and the disposition was deferred to this
gate-moment record.

## Ruling

Register the three files as co-abap variant-identity assets. The frontmatter
of each file states a distinct SAP-domain role, so the correct category is
identity, not consumption and not drift. The rows land in both schema copies
in one commit, exactly as DEC-20261103-02 placed the co-architect row.

## Verification

`bun test tests/unit/hub-topology-legs.test.ts` — the case-6 real-workspace
pin asserts zero fails for co-abap after the rows land, and the
security-monitor assertion (an E4 variant-identity row, already sanctioned)
stays green. `bun scripts/validate-templates.ts` and `bun scripts/audit.ts`
must stay green; the nightly scaffold E2E legs for co-abap follow in CI.
