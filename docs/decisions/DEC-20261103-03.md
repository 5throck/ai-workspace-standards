## Decision context

T-20261103-007 is the 5th occurrence of the co-newbiz gitleaks test-fixture
class: generic-api-key fires on throwaway local test-user passwords
('pw-gi-analyst-123', 'pw-p2c-analyst-123' — T-20261028-009;
'pw-analyst-12345' — T-20261030-005; 'pw-carol-12345' x2 + 'pw-closed-again-123'
— commit 3c8d983d) that the tests themselves create for a scratch SQLite user
and destroy on teardown, plus the same-shaped family of process-stage SSOT
registry keys ('s8.business_case' et al. — T-20261029-006;
's4.route_recommendation' — pm-catalog.test.ts). Nothing external accepts any
of these values. T-20261030-005's resolution directed that a 5th landing
triggers a structural fix rather than another per-file entry; the PM
adjudicated policy (a) — a bounded path+shape allowlist applied once.

The dispatch brief paraphrased the flagged findings as "key: 'k'",
"key: 'rag:absent'", "snapshot_hash: 'abc'" (such literals do exist in
co-newbiz tests: assume.test.ts assumptionKey 'k', gate-proposal-confirm-p2.test.ts
acknowledgements key 'rag:absent' with snapshot_hash 'abc'). A controlled
shape probe (gitleaks 8.30.1, 2026-11-03) showed generic-api-key does NOT flag
those four literals ('k', 'rag:absent', 'abc', and metric_key 'npv') — value
too short / no keyword+entropy fit — so no allowlist shapes are added for
them; the rule covers exactly what the scanner actually flags.
