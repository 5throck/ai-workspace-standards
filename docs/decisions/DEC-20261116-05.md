decision: >-
  Gate-moment design amendment (Amendment A) to
  2026-11-16-co-deck-pdf-html-backport-design.md section 7.2, ruled before the
  PR-1 QA gate. Finding (automation-engineer, verified by architect against
  templates/co-deck): buildSizes derives T_PUNCH_TAG from the merged
  fonts.punchline_sub_px (gen-slides-pdf.ts:2283,
  pt(f.punchline_sub_px with nullish fallback 12.0, 12.0)), so the PR-1
  zen theme-spec default
  punchline_sub_px: 46 renders the gold punchline PART tag at 34.5pt
  (46 x 0.75 zen calibration) instead of the pre-PR-1 12pt (16 x 0.75) on
  zen punchlines that draw the tag (non-cardMode slides with a non-empty
  data.section; bgDrawn/cardMode slides draw no tag and are unaffected).
  The coupling predates PR-1 — any deck's layout_overrides
  fonts.punchline_sub_px silently moved the tag; the theme-spec default
  surfaced it fleet-wide. RULING: option (a), refined — give the tag its own
  key bound at Layer 0 to the output-neutral value 16.0, NOT the 12.0 the
  finding's option (a) sketched: pt()'s fallback argument is also CSS-px
  through the per-theme calibration (pt = (cssPx with nullish fallback)
  x mult, gen-slides-pdf.ts:2239-2240), so a 12.0 default would shrink the
  tag on
  every deck (9pt zen / 10.2pt base-calibration), a worse regression than
  the one fixed; 16.0 reproduces the pre-PR-1 chain exactly (every theme
  inherited punchline_sub_px: 16.0 from layout_base.json, tag = 16 x mult).
  Exact amendment for dispatch: gen-slides-pdf.ts fonts interface gains
  punch_tag_px?: number (no legacy _pt twin); buildSizes T_PUNCH_TAG becomes
  pt(f.punch_tag_px with nullish fallback 16.0, 16.0);
  _shared/layout_base.json fonts gains
  "punch_tag_px": 16.0 (output-neutral); NO zen pdf_layout_spec.json entry
  (zen tag stays pre-PR-1 size); LH_PUNCH_TAG untouched. Option (b) (bind
  the tag to Layer-0's sub value) rejected: buildSizes receives only the
  merged spec (no Layer-0 access without new plumbing) and it inverts the
  semantics. The line_heights namespace already split punch_tag_px from
  punch_sub_px (layout_base.json) — this applies the same split to fonts,
  the house pattern. Lands in PR-1 (same PR as the finding); PR-3's
  pdf-export key table lists fonts.punch_tag_px; changelog notes decks that
  moved the tag via punchline_sub_px must now set punch_tag_px explicitly.
  Design doc sections 7.2 (item 4), 12 (PR-1 file list), and 13 (acceptance
  bullet, Amendment A) updated; templates/, scripts/, and tests untouched by
  the ruling itself.
alternatives: >-
  (bind T_PUNCH_TAG to Layer-0 punchline_sub_px, REJECTED) buildSizes has no
  Layer-0 access — new plumbing for worse semantics; (new key with Layer-0
  default 12.0 as sketched in the finding, REFINED) 12.0 is a CSS-px value
  through the calibration and would shrink the tag fleet-wide (9pt zen,
  10.2pt base) — 16.0 is the output-neutral default; (leave the coupling and
  drop the zen punchline_sub_px default, REJECTED) forfeits the U-20261116-011
  parity fix for a latent bug the decoupling fixes at the root.
