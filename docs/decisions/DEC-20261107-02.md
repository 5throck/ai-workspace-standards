## Decision context

The external-deps machinery (pinned shallow clones, compat-gated pin moves,
vendoring guard) was promoted to the templates on 2026-11-07. The parts of
the co-work ppt-master pattern that it left behind — the as-is coupling
contract, the license posture, and a project-runnable verify surface — still
existed only as prose in DEC-20261106-04 and one adapter comment. The
standard design promotes them. Its §12 carried five open questions that
needed an explicit user ruling before implementation: the seven-file template
wave exceeds the architect threshold; the license class table, in particular
GPL used as separate processes; the reversal of the one-day-old machinery D1
decision; a fleet drift scan; and the strength of the `external/<id>`
install-dir convention. On 2026-11-07 the user ruled on all of them via
structured questions and approved the design.

## Ruling

1. **R1 — Single wave.** All seven template files land in one PR. The
   high-risk threshold is accepted for this wave.
2. **R2 — License table approved; D1 reversal confirmed.** allow =
   MIT/Apache/BSD and the rest of the design's allow list; review = LGPL and
   the rest of the review list; review (standalone) = GPL tools that run only
   as separate processes, attested by a `license_decision` record — without
   the record the entry is treated as linking GPL; deny = AGPL, linking GPL,
   and any unknown id. The machinery design's "no license field" decision is
   reversed: `license` is a required v2 manifest field.
3. **R3 — Hard FAIL on new entries.** A new entry (no recorded `commit`)
   whose `install_dir` is not `external/<id>`, and any entry whose
   `install_dir` collides with another entry's, is refused. Already-installed
   entries are grandfathered with a WARN.
4. **R4 — Drift scan follow-up.** Filed as T-20261107-006; not in this PR.
