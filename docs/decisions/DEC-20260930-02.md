## Ruling

1. **Accept forward-only.** `tier_semantics: floor` and `session_hosted: true`
   stay in the L0/L1 templates and reach new scaffolds only. No fleet backfill.
2. **The semantics are not lost to the fleet.** The "PM Tier Semantics" rule
   (floor, higher model allowed, below-floor warning) lives in the COMMON-AGENTS
   zone of `AGENTS.md`, and the upgrade pipeline merges that zone into existing
   projects (design follow-up C, verified by dry run). What the 13 copies lack
   is the duplicated frontmatter metadata, not the rule.
3. **No consumer exists.** No validator or script reads these keys today
   (design follow-up B details). There is no functional gap to close.
4. **Revisit trigger.** If a future validator or script starts consuming
   `tier_semantics` / `session_hosted`, open a fleet backfill wave at that time;
   the natural vehicle is a per-project upgrade touch, not a standalone sweep.

## ADR assessment

No ADR required. This records a non-action: it preserves the existing
project-ownership contract and the already-landed delivery design
(2026-09-29-pm-tier-capability-floor-design follow-ups B/C). No gate, schema,
or validator changes.

## Consequences

- Fleet pm.md frontmatter stays divergent; `git grep tier_semantics Projects/`
  returns nothing, and that is the accepted state.
- `validate-templates.ts` keeps enforcing contract version 1.2.1 against the L1
  template only; the fleet copies remain under project ownership.
- The ticket T-20260930-005 closes with this decision; no specialist dispatch
  and no code change follow from it.
