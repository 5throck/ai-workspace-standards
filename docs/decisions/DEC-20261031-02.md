## Decision context

Two variant upgrades halted today on the same delivery-conflict class: the
generic SYNC policy cannot deliver a template-changed JSON config file into a
project copy that carries committed project evolution — preserve fails the
new consumer's audit, adopt clobbers the project's committed gate config. The
user's standing directive today ("문제가 있는 부분은 수정해주고 반영해줘") covers
fixing the blockage, so this record fixes the adjudication now instead of
queueing it behind a proposal gate. Status `accepted` records the Option A
selection; the design doc carries Status `Approved (2026-10-31, PM per user
mandate)` and implementation dispatches through the PM Gateway on that basis.

## Conditions attached

1. Implementation stays inside the design's scope: one policy, one pure
   helper, one engine branch, unit tests. Any discovered need to change
   baseline manifest structure or add override shapes returns to PM.
2. The co-price and co-architect re-runs use dry-run first; the dry-run MERGE
   verdict (landed / preserved / TEMPLATE_DELTA lists) must match the apply
   outcome before apply proceeds.
3. Post-delivery `bun scripts/audit.ts` must be green in both projects —
   design-lint gate and mirror-parity guard included — before the halts close.
4. Every future schema-changing upgrade reviews TEMPLATE_DELTA rows in the
   decision log; an operator who wants the template value uses
   `--disposition adopt-template=docs/workspace-schema.json` and records why.
