## Ruling

1. **Ruling 1 basis (verbatim, 2026-10-26).** The user ruled on T-20261026-018:

   > "정규화가 필요하다고 생각해. agents/*.md에는 high/medium/low 선언이 맞고,
   > high/medium/low에 매칭되는 어떤 모델을 사용할 지에 대해서는 SSOT를 참고해서
   > 적용하는 방식으로 진행되어야 해."

   Translation: "Normalization is needed. agents/*.md should declare
   high/medium/low; which model matches high/medium/low must be resolved by
   consulting the SSOT."

2. **Normalization decided (ruling 1).** Agent frontmatter stops declaring
   tier per platform. Each `agents/*.md` file (workspace root 9, L1 2, L2 148,
   and the 16 `Projects/co-*` copies) declares one scalar
   `tier: high|medium|low`. No per-platform lines, no `# model-id` comments.
   The 9 co-price agents whose mixed blocks are #723 scaffold artifacts
   collapse to their `claude` value; the 4 block-less `extends:` stubs gain
   `tier: medium`. The map form survives only as a legacy shape that validator
   v2.0.0 tolerates with a loud WARN until the fleet converges (design D3).

3. **Ruling 2 basis (verbatim, 2026-10-26).** On the design's D1 (keep
   `agent_tiers` as a root-scoped hook roster with inert delivered copies),
   the user ruled:

   > "agent_tiers는 개별 프로젝트에서 무의미한 루트 로스터 잔재 — 제거 필요"

   Translation: "agent_tiers is a meaningless leftover of the root roster in
   individual projects — it needs to be removed."

4. **`agent_tiers` removal decided (ruling 2).** The block is deleted from
   `docs/workspace-schema.json` (root) and its byte-identical L1 copy
   (`templates/common/docs/workspace-schema.json`). The schema keeps `models`
   as its only tier-related block. Single-declaration principle: the agent
   file's scalar `tier:` line is the only tier declaration everywhere, root
   included. Consumers move with the removal — the root-only
   `agent-model-gate.ts` reads the agent file frontmatter (+ `models.claude`)
   instead of the schema roster; `lifecycle-sync-audit.ts` Check F drops the
   `agent_tiers`-vs-frontmatter axis; `validate-templates.ts` WS-01 Check 4
   retires; validator v2.0.0 has no `agent_tiers` parity axis. Design D1 is
   amended in place with the marker "(D1 revised 2026-10-26 per user ruling 2:
   removal, not root-scoping)"; ADR-0102 records the formal supersession. The
   roster of workspace-root agents lives in `agents/*.md` and AGENTS.md §1.

5. **SSOT answer (ruling 1, as revised by ruling 2).** `docs/workspace-schema.json`
   is the SSOT for the platform→tier→model mapping (`models` block, resolved
   at dispatch/validation time). With ruling 2 it is the schema's ONLY
   tier-related block — there is no schema-side tier roster.

6. **Design Gate Row 0.** Satisfied by the registered design
   `2026-10-26-model-registry-platform-coverage`
   (`docs/designs/2026-10-26-model-registry-platform-coverage-design.md`, spec
   status `planned` in `docs/specs/registry.json`). Both rulings approve the
   design direction (ruling 2 revising D1); ADR-0102
   (`docs/adr/0102-agent-tier-scalar-declaration.md`) records the formal
   supersession of constitution 05 §5.1/§5.6 map-form rules,
   DEC-20261023-01 D4 (the per-agent hermes/zai frontmatter lines) and its
   ruling item 6 frontmatter-twin deliverable, the schema-side `agent_tiers`
   registration, and the per-agent-frontmatter expectation inherited from
   ADR-0088 (hermes stays a fully validated `models` platform).

7. **Implementation authorized (design §8.3 — never fleet-red).** Order is
   binding: the transition-capable validator lands BEFORE any tree is
   normalized.
   - **PR-1 (root)**: ADR-0102, constitution 05 rewrite, this DEC record,
     validator v2.0.0 (D3 semantics), apply script, root 9 agents normalized,
     schema `agent_tiers` removal with consumer updates, docs wording. Root
     ends PR-1 fully normalized and green.
   - **PR-2 (templates)**: apply script over L1 (2) + L2 (148, including the
     co-price collapse and the 4 stubs) with version bumps and
     `last_updated` refresh; validate-templates/audit/managed-block-parity
     green. >3 template files → high-risk flag; this record is the user
     confirmation.
   - **L0→L1 publish**: validator v2.0.0 twin and the schema copy (now
     without `agent_tiers`) to `templates/common/`.
   - **Fleet wave**: upgrade delivery + apply `--projects` pass across
     `Projects/co-*` (16), including the two orphaned projects and the
     stub-resolved pm/i18n files the upgrade pass never re-delivers (D4);
     delivered schema copies shed the stale root-9 roster on next delivery.
   - **Convergence follow-up** (ticket, not this work): after a zero-legacy
     soak, flip delivered-context missing-tier severity to FAIL (v2.1.0).

8. **Alternatives rejected** as recorded in the frontmatter: (a) the
   144×3-line patch + validator hardening, (b) a `tier_overrides` grammar,
   (c) keeping `agent_tiers` as a root-scoped roster with inert delivered
   copies (the pre-ruling-2 D1).
