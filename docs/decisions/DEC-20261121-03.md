## Context

CI run 43705458736 (2026-11-15) showed the windows "Run unit tests" step at
361s vs 41s on ubuntu (8.8x), with 62% of the time in ten ≥30s files dominated
by full `upgrade-project.ts` engine subprocess spawns (each ~10–15s on win32:
bun process + bun grandchildren + template-tree copy), Defender real-time
scanning multiplying every copy and process start, 311 one-file-per-process
`bun test` invocations, and a ~4-worker pool on a spawn-wait-heavy workload.
The design was drafted 2026-11-15 and gated 2026-11-16 (items 1–5, user
approval); the implementation landed the same day through the PM Gateway in a
single PR (#2044), spec registered implemented. The soak that followed
(CI run 43788899945) falsified two of the five projections, and both were
resolved onto the design's pre-authorized mitigation paths within
test-runner v1.17.0 → v1.17.1 — those two outcomes are the substance of this
ruling, recorded here because the gate moment itself never got a DEC.

## Decision

As recorded in the frontmatter: items 1–5 approved 2026-11-16 and shipped via
PR #2044; batching shipped OFF behind `TEST_RUNNER_BATCH_SIZE` (v1.17.1,
default 0) after the soak regression; win32=6 reverted to the
`min(availableParallelism(), 4)` default with the A/B continuing via
`TEST_RUNNER_CONCURRENCY`; related ruling — the quickdl consumption-field
backport rode E3 as QuickDL PR #50 (2026-11-21). Full design:
`docs/designs/2026-11-15-windows-ci-test-speedup-design.md` (§3.3 batching,
§3.4 concurrency, §5 validation plan).

## Consequences

As recorded in the frontmatter. Governing surfaces:
`scripts/test-runner.ts` (batching machinery + env knobs, @1.17.x),
`templates/common/scripts/test-runner.ts` (propagated twin),
`.github/workflows/test.yml` (Defender step, bun 1.4.4 pins at both
occurrences), the four consolidated unit test files, and — recorded as the
related ruling — QuickDL's `variant.json` (`consumption: "adoption-only"`,
PR #50).
