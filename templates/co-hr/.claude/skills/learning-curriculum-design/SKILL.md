## Context

Use in Phase 2 whenever an engagement requires designing training/learning capability. Owned by the Learning & Development Specialist. Competency development plans link forward to `career-path-succession-planning`'s individual development plans, and evaluation of any program tied to performance ratings should reference `performance-system-design`'s cascade structure.

## When to Use

- When a training needs analysis is requested
- When a competency model needs to be built or revised
- When a learning curriculum or learning journey needs to be designed
- When a training program is being scoped and its evaluation plan has not yet been defined

## Execution Steps

1. **Training Needs Analysis (TNA)**:
   - Conduct analysis at three levels per standard TNA practice: org-level capability gap, role-level competency gap, individual development need
   - For each level, state the evidence source (e.g., strategy documents for org-level, job architecture/competency gaps for role-level, performance/development conversations for individual-level)
   - Do not skip a level — a training request scoped only at the individual level without checking org/role-level context risks solving the wrong problem

2. **Competency Model Design**:
   - Define competency categories: core (org-wide), leadership, and functional (role-specific)
   - For each competency, define behavioral indicators per proficiency level (e.g., foundational/proficient/advanced) — indicators must be observable behaviors, not abstract traits
   - Cross-check functional competencies against the job architecture (if available from `org-design-framework`) so functional competencies align with job families/levels

3. **Curriculum Architecture**:
   - Design the learning journey by role/level, sequencing content logically (foundational before advanced)
   - Specify the format mix per journey stage: instructor-led, e-learning, on-the-job, mentoring — justify format choice against the content type and audience, not a single default format
   - Map each curriculum item to the competency/behavioral indicator it develops (traceability back to Step 2)

4. **Program Evaluation Planning (Kirkpatrick Four Levels)**:
   - Every program design must specify its evaluation plan at intake, not as an afterthought — define, for each program:
     - Level 1 (Reaction): how participant satisfaction will be measured
     - Level 2 (Learning): how knowledge/skill gain will be measured
     - Level 3 (Behavior): how on-the-job behavior change will be measured, and when (post-program interval)
     - Level 4 (Results): what business/organizational metric the program is expected to move, and how attribution will be handled (label as hypothesis unless statistically validated)
   - Flag any program submitted for design without a Level 3/4 plan as incomplete

## Output Format

- **Training Needs Analysis Report**: Level (Org/Role/Individual), Gap Identified, Evidence Source
- **Competency Model**: Competency, Category (Core/Leadership/Functional), Level, Behavioral Indicator
- **Curriculum Map**: Role/Level, Journey Stage, Format, Competency Mapped
- **Evaluation Plan per Program**: Program Name, Level 1-4 Measurement Method, Level 3 Measurement Interval, Level 4 Target Metric (hypothesis-labeled if unvalidated)
