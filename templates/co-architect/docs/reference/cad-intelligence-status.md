Fixed a real replay-fidelity bug found while wiring this up: the legacy `Hypothesis` adapter only round-tripped a single `target_id`, silently truncating multi-target room hypotheses (4 walls → 1) and changing `_build_graph()`'s edge count between a run and its replay — now the full `target_feature_ids` tuple is stashed in `metadata["_target_feature_ids"]` when there's more than one. **TOPOLOGY/SYMMETRY/ROOM_RATIO now fold into the unary potential**: a room hypothesis's blended confidence is `mean(own confidence_mean, *matching same-component TOPOLOGY/SYMMETRY/ROOM_RATIO evidence confidence_mean)` — matched via `extract_component_id()` on each evidence's evidence_id, computed once per `optimize()` call (`_blended_confidences()`), then used for both the ICM accept/reject score and the reported `final_energy` diagnostic. Opening hypotheses and rooms with no matching unary evidence are unaffected (blended == own confidence). CLEARANCE remains unwired — its point↔line relation doesn't map onto a single room/opening/wall variable as directly as the others do, and deciding which one it should attach to needs its own design pass — deferred. 175/175 `tests/test_reasoning_*.py` pass (192/192 after the real-CAD calibration workflow was added — see the header above). **Two-representation pipeline fork (ADR-015)**: `_build_evidence_repository` now produces two line sets per component — a **bridged** set (new public `geometry/space_geometry.py::weld_and_bridge_for_polygonization()`, reusing the existing `_weld_endpoints_v1` + `_bridge_door_window_gaps`) fed to `polygonize_full`/`compute_component_features`, and the **original gapped** set fed to `find_wall_discontinuities` (OPENING_SYNTH) — so a door in a room's exterior wall both closes the room (bridged) and registers as an opening (gapped), activating `DOOR_ACCESS` on the realistic apartment-data case that PR #207's interior-gap workaround could not cover. Apartment golden is unchanged until its fixture is upgraded to real wall gaps (follow-up). See [`PLAN-2026-08-01-ARCHITECTURAL-REASONING-ENGINE`](../superpowers/plans/2026-08-01-architectural-reasoning-engine.md) and [`DESIGN-2026-08-01-ARCHITECTURAL-REASONING-ENGINE`](../superpowers/specs/2026-08-01-architectural-reasoning-engine-design.md). |

They are not competing plans — M1–M5 is an **execution-order roadmap for co-architect's actual current codebase** (bug fixes first, then features), while Phase1–Phase6 is a **layer-completion roadmap for the vision architecture**.
