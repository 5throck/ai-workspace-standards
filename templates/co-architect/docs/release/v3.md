### Code Improvements (WP1–WP2)

- **MCP Tool Cleanup (WP1)**: Removed 8 orphaned ELEV-001 tool schemas and dispatch entries. Added `zwcad_build_object_candidates` to `_TOOLS_LIST` (phantom tool fix). Wired `handle_group_openings` into `_TOOLS_LIST` + `_TOOL_DISPATCH`. Tool count: 47 (matched in both lists).
- **Axis Split/Merge Detection (WP2a)**: Added `AXIS_SPLIT` and `AXIS_MERGE` exception codes to `axis_grid.py`. Implemented two-pass detection algorithm in `reconcile_axis_grid()`. Added 3 new unit tests.
- **Opening Assignment Cleanup (WP2b)**: Removed dead constants `CONFIDENCE_GAP_PLUS_SYMBOL` and `CONFIDENCE_GAP_ONLY` from `opening_assignment.py`. Fixed stale comment (0.7 → 0.65). Updated tests to use inline values.

### Transaction Layer (WP4)

- **TransactionManager** (`src/cad_intelligence/platform/transaction.py`): Full transaction lifecycle — `begin → pre_validate → execute → post_validate → commit/rollback`. COM-free design with `RollbackExecutor` protocol. `NullRollbackExecutor` for tests; `UndoRollbackExecutor` interface for ZWCAD integration (M4+).
- **ActionResult**: Structured handler return type with `success`, `warnings`, `artifacts`, `duration_ms`.
- **ValidationResult**: Pre/post validation result with `passed`, `errors`, `warnings`.
- **RecoveryReport**: Full transaction diagnostics with `transaction_id` (UUID), `status` (committed/rolled_back/failed), `duration_ms`, `commands`, `rollback` flag, `warnings`, `artifacts`, `snapshot_path`.
- **RollbackPolicy**: ATOMIC (default, all-or-nothing) and PARTIAL (opt-in, interface ready).
- **28 COM-free unit tests** (`tests/test_transaction.py`) covering all scenarios: success, failure, rollback, pre/post validation, warnings aggregation, custom rollback integration.

### Open Plan Boundary Reconstruction (WP5)

- **DividerLine** (`common/models.py`): Frozen dataclass with direction-normalized ID (`sorted(start, end)` before SHA-1), `source_type`, `confidence`, `metadata`. Factory method `DividerLine.create()` for deterministic ID generation.
- **Divider Pipeline** (`geometry/space_geometry.py`): Full 7-component pipeline — `DividerProvider` protocol → `DividerResolver` (first/merge mode) → `DividerScorer` (pluggable `ScoringStrategy`) → `DividerValidator` (per-divider `DividerValidation` with rejection reasons) → `DividerProcessor` (normalize → snap → merge → inject → `DividerPipelineResult`).
- **6 Providers** (priority order): `RoomMetadataDividerProvider` (0.95, implemented), `GraphConstraintDividerProvider` (0.80, implemented — uses Semantic Graph wall adjacency + door continuity), `LayerDividerProvider` (0.30, signal only), `AnnotationDividerProvider`, `AIInferenceDividerProvider`, `VoronoiDividerProvider` (stubs).
- **SpaceDetectionConfig**: Pipeline-level frozen config (thresholds, tolerances). Provider-specific settings scoped to each constructor.
- **SpaceDetectionContext**: Generalized context object (room_info, drawing_metadata, graph, space_polygons) with future expansion points.
- **ScoringStrategy Protocol** + `WeightedScoringStrategy`: Pluggable scoring — `0.7 × base_source_confidence + 0.3 × provider_raw`. Swappable for future `MLScoringStrategy`.
- **DividerPipelineResult**: Structured result with `generated_lines`, `warnings`, and `statistics` (candidates, accepted, rejected, reasons, provider, strategy).
- **_build_space_polygons**: New `divider_lines` parameter (additive, backward compatible) — divider LineStrings injected as temporary walls before polygonization.
- **64 COM-free unit tests** (`tests/test_open_plan.py`) covering all pipeline components, models, and integration scenarios.

## Upgrade Guide

### For MCP Client Developers

1. Run `tools/list` to verify your client receives the updated 47-tool list.
2. Remove any references to the 8 deprecated ELEV-001 tools.
3. If using opening grouping, use the new `zwcad_group_openings` tool.
4. Check for `AXIS_SPLIT` / `AXIS_MERGE` exceptions in axis reconciliation output.

### For Pipeline Developers

1. Read [`PIPELINE-001-design.md`](../designs/PIPELINE-001-design.md) for the authoritative phase flow description.
2. Refer to [`GRAPH-001-design.md`](../designs/GRAPH-001-design.md) for node/edge type definitions.
3. Follow [`API-001-design.md`](../designs/API-001-design.md) for handler registration conventions.
4. All schema changes must go through ADR-005 (see GRAPH-001 §9).

### For Test Developers

1. New tests follow [`TEST-001-design.md`](../designs/TEST-001-design.md) verification strategy.
2. Performance benchmarks include memory budgets (see TEST-001 §1.5).
3. Mutation/failure injection tests should cover the scenarios in TEST-001 §1.4.
